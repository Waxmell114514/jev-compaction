# jevctx 的论文价值在"可逆 + 缓存友好"，不在"剪得多"

**结论先行：jev-compaction（`jevctx`）五个机制逐个拆开看，没有一个是全新的，但它们的组合——"由只打分不生成的判断模型做准入、被移走的内容可逐字节找回、重写只在算得过账时才做"——在 2024–2026 的文献里确实没有人作为论文主题做过，也没有任何上线的 harness 把"压缩后保住 prompt cache"当成一等设计目标。** 真正的空白有四处：role-typed 的准入门控及其带来的"被删掉但后来要改的代码"这一指标；带 profile 过滤与判断模型重排的 `recall`（尤其是去掉标识符的查询）以及 harness 主动代为 recall；带剩余轮数项的闭式缓存重写判据；以及用影子日志里"后来被用到"来拟合阈值。已经被别人做掉的部分同样明确：admission 时用独立小模型剪 tool output（SWE-Pruner）、goal conditioning 无用（SWE-Pruner Pro）、一行指针占位且原始 transcript 不改（OpenCode/Pi/Anthropic API）、逐字节 expand（三篇 2026 工作）、supersession（Concord、DCP）、"只截断不改写"（CliffCompaction）。当前实验离顶会标准很远：21–24 个实例、每臂一次、免费模型、假设价目表，而这个领域的接受线是 200–500 个实例、至少两个模型、三个 seed、真实价目、paired bootstrap 置信区间；单次运行的 SWE-bench Verified pass@1 本身就有 2.2–6.0 个百分点的噪声，所以目前所有 resolve-rate 结论都不可区分于噪声。最有希望的论文主题不是"role gating 剪得更准"（那条赛道已经拥挤，且 ~26% 的削减量处于 SWE-Pruner 区间下沿、远低于 masking 的 ~50% 成本削减），而是**"无损上下文管理：以可恢复性和缓存调整后成本为评价轴的 harness 侧准入策略"**，把 break-even 重写判据与可逆省略作为论点，role gating 和 supersession 作为机制章节。合适的落点是 SE 会议（ASE 2027、FSE 2028）或 MLSys，而非 ICLR/ICML 主会；可行的路线是先用离线回放（确定性、便宜）拿到缓存经济学结果投 2027 年初的 workshop，再补 200–500 实例、双模型、三 seed 的在线实验投 ASE 2027（约 2027 年 3 月）。要真正影响 harness 设计，论文本身不够：需要一个可直接插入 OpenHands/mini-swe-agent/OpenCode 的开源组件、一个不依赖专有 Jev 的开放替代判断模型、一个有记忆点的概念名，以及按真实价目报告的可复现数字。

## 逐项对照：五个机制中四个有直接先例，空白在组合与评价指标

下表给出每个机制的判断。"已被做过"指有公开文献或上线产品实现了同一机制；"空白"指研究笔记里的多轮检索未找到先例（不等于证明不存在）。

| 机制 / 性质 | 最接近的先例 | 已被做过的部分 | 仍属空白的部分 | 判断 |
|---|---|---|---|---|
| Admission gating + role profile | SWE-Pruner、SWE-Pruner Pro、Squeez、TRACER、AgentDiet | admission 时独立小模型逐段决定保留；goal conditioning 无增益 | 按"在修改流程中的角色"（change_site / evidence / navigation / noise）门控；"被删但后来被编辑"指标 | 机制部分新，赛道拥挤 |
| `expand` / `recall` | `recall_event`（arXiv 2609.20804）、`context_recover`（2610.10590）、OpenDev、Manus | 逐字节 expand；指针占位 | profile 过滤 → BM25 → 判断模型重排；去标识符查询；harness 主动 recall | recall 的设计是真空白，但先例显示 agent 几乎不用 |
| Supersession | Concord（2610.05281）、OpenCode DCP、AgentDiet "expired"、Claude Code Read 工具 | 同命令重跑去重；文件改动后标记过期 | 仅从 transcript 推导（无文件监听）；21% 过期比例这一实测数据 | 工程组件，不是论文论点 |
| Cache-aware work area | TokenPilot、CliffCompaction、AgentDiet s−a 编辑、Anthropic `clear_at_least` | 承认重写会破坏缓存并设阈值 | 带 turns_left 的闭式判据；冻结前缀 + 工作区的划分 | 形式上新，但依赖固定先验，且强烈依赖模型价目 |
| Shadow calibration | TRACER（RL 回报含再调用惩罚）、SWE-Pruner 教师标签 | 从 rollout 结果学保留率 | 从影子日志的"后来是否被用"拟合准入阈值 | 真空白，但贡献量级偏小 |
| Injection quarantine | Anthropic auto-mode probe（标记并警告）、AgentDojo PI detector | 在 tool result 进入模型前做筛查 | 以不引用原文的指针隔离 | 槽位相同、机制更强；评估远不达标 |
| "只含原文、无生成记忆" | Selective Context、RECOMP、CliffCompaction、rate–distortion 论文 | 抽取式压缩的结构性性质；"只截断不改写" | 把它命名为安全性质并与非生成判断模型结合 | 可作为 framing，不能作为实证贡献 |

**准入门控**。SWE-Pruner 已经在 admission 时用一个 0.6B 的独立 skimmer 逐行剪 tool output，在 500 个 SWE-bench Verified 实例上报告 23–38% token 削减、27–36% 成本削减、resolve rate 持平 ([arXiv 2601.16746](https://arxiv.org/html/2601.16746v1))；其后继 SWE-Pruner Pro 去掉了独立模型和 goal hint，直接读 agent 自身隐状态 ([arXiv 2607.18213](https://arxiv.org/html/2607.18213))。`jevctx` 离线发现"intent 不显著优于无 intent"（最佳 ΔAUC +0.014 [−0.009, +0.042]）([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md)) 与 Pro 的结论一致——这是一个被复现的发现，不是任何一方的新意。项目真正没有先例的是 role 标签：TRACER 按**工具类型**学保留率 ([arXiv 2608.29363](https://arxiv.org/html/2608.29363))，AgentDiet 按**浪费类型**（useless/redundant/expired）分类 ([arXiv 2509.23586](https://arxiv.org/html/2509.23586v2))，SWE-Pruner Pro 有一个 "skeleton" 标签，但没有人按"这段是要改的代码、是证据、还是导航"门控。**role gating 把"被省略但后来被编辑的记录"从 21 降到 11，离线把同等削减量下的损失从 14% 降到 9%**，这个机制和这个指标都站得住 ([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md))。但要注意 Complexity Trap 已经把这条赛道的地板抬得很高：不调用任何模型、只把 M=10 轮之前的观测换成占位符，就在 SWE-agent 上把成本砍半（Qwen3-Coder-480B：$1.29 → $0.61，solve 53.4% → 54.8%）([arXiv 2508.21433](https://arxiv.org/html/2508.21433v3))。`jevctx` 的 ~26% admission 削减和 ~10% 成本削减与之相比不占优势，所以论文的卖点不能是"删得多"，只能是"删得对、可找回、缓存不破"。

**expand / recall**。逐字节 expand 已有至少三个 2026 年的直接先例：哈佛—Adobe 等团队的 harness 设计实证研究实现了 elision stub + `recall_event(id)` 逐字返回原文 ([arXiv 2609.20804](https://arxiv.org/html/2609.20804))；Franke 的 agent-controlled forgetting 用 `context_recover(archive_ref)` 做逐字节归档恢复 ([arXiv 2610.10590](https://arxiv.org/html/2610.10590v1))；OpenDev 把超过 8,000 字符的输出卸载到 scratch 文件并留 500 字符预览 ([arXiv 2603.05344](https://arxiv.org/html/2603.05344))。更关键的是这些先例的发现与 `jevctx` 的在线观察完全一致：**agent 自己几乎不用 recall**——harness 研究中 T2 比 T1 只差 −0.36 分，64 个设置里 36 个从未调用 `recall_event`，128k 预算下平均 0.007 次/任务 ([arXiv 2609.20804](https://arxiv.org/html/2609.20804))；Franke 的核心对照里恢复调用次数为零 ([arXiv 2610.10590](https://arxiv.org/html/2610.10590v1))；`jevctx` 在线约每 20 次运行用一次 ([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md))。所以 `expand` 本身不能当贡献。`recall` 的三层设计（profile 过滤 → BM25 → Jev 重排）是真空白：记忆系统的检索栈是 embedding 优先、图/关键词兜底，没有"BM25 候选 + 小判断模型重排"的组合；AMA-Bench 还给出了理论支撑——相似度检索对机器生成的证据不可靠，23.5% 的情况需要精确关键词 ([arXiv 2602.22769](https://arxiv.org/html/2602.22769v4))。没有任何记忆论文评估过去掉标识符的查询，`jevctx` 的 **69% vs BM25 18%** 是新设置 ([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md))。harness 主动代为 recall 也没有先例，最近的只是 Claude Code 压缩后按最近访问恢复 5 个文件这种固定启发式 ([arXiv 2609.00006](https://arxiv.org/html/2609.00006))。

**Supersession**。这是项目里先例最密的一块。Concord（2026 年 10 月 4 日，SOSP 2026 AgenticOS workshop）把每条观测链接到源文件、用 SHA-256 检测变更、无模型调用地刷新/标注/抑制过期块，在构造的基准上比最强非 oracle 基线少 46.4% token ([arXiv 2610.05281](https://arxiv.org/html/2610.05281v2))；OpenCode DCP 插件做同工具同参数去重 ([GitHub](https://github.com/Opencode-DCP/opencode-dynamic-context-pruning))；Claude Code 的 Read 工具已经拒绝未改动文件的重复读取 ([claude-code #60684](https://github.com/anthropics/claude-code/issues/60684))。`jevctx` 的三条规则是 Concord 机制的严格子集。它唯一独有的是一个实证数据：在 28 次真实 SWE-bench 运行里 **21% 的 tool-output token 因 agent 自己的编辑而过期** ([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md))——Concord 明确没有测量真实运行中的过期率。这是一个有价值的段落，不是一篇论文。Concord 发布于十天前，审稿人一定知道它，必须正面对比。

**Cache-aware work area**。没有人写出 `dropped × turns_left × read_price > rest_of_tail × (write − read)` 这个不等式或任何带剩余轮数项的闭式规则，这一点可以确认。但组成部分全部公开：Anthropic 的 context editing 文档明说清理会使缓存前缀失效、要"清掉足够多的 token 让缓存失效值得"，并提供 `clear_at_least` 旋钮 ([Claude Platform docs](https://platform.claude.com/docs/en/build-with-claude/context-editing))；TokenPilot（EMNLP 2026 Findings）命名了"文本稀疏性与 prompt cache 连续性的权衡"，但成本模型没有写入价、没有时域项 ([arXiv 2606.17016](https://arxiv.org/html/2606.17016v2))；CliffCompaction 指出任何修改都要从公共前缀重新 prefill、未缓存 token 贵 5–6 倍、靠"偶尔压缩"摊销，但只用 token 阈值触发 ([arXiv 2609.26779](https://arxiv.org/html/2609.26779))；AgentDiet 只编辑第 s−a 步来限制失效范围 ([arXiv 2509.23586](https://arxiv.org/html/2509.23586v2))。所以正确的定位是"第一个把决策规则写成显式、依赖时域的形式"，不是"第一个注意到这个权衡"。两个弱点必须正视。第一，`turns_left` 来自固定先验，而文献常态是在线估计剩余预算，且 BAGEN 发现 agent 自己估得很差（r = 0.35）([arXiv 2606.00198](https://arxiv.org/pdf/2606.00198))；`jevctx` 自己的 `work2` 实验也显示更保守的先验让重写次数减半、请求只小 6%、落入噪声 ([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md))。第二，判据的结果强烈依赖价目：按 Anthropic 当前价目，Sonnet 4.5 的 `(write − read)/read` 是 11.5（5 分钟 TTL），Sonnet 5.5 是 24，Fable 5.1（cache read 0.025×）是 49——在最新模型上重写尾部几乎永远不划算；而在 OpenAI GPT-5.6 之前、Gemini 隐式缓存、Grok 等免写入费的提供商上，写入溢价项直接消失，公式退化为一次性全价 re-prefill 的比较 ([Anthropic pricing](https://platform.claude.com/docs/en/docs/build-with-claude/prompt-caching); [OpenAI](https://developers.openai.com/api/docs/guides/prompt-caching); [OpenRouter](https://openrouter.ai/docs/features/prompt-caching))。论文必须把"约 10% 成本削减"报告成 `(write − read)/read` 的函数，而不是一个数。还有一个潜在的釜底抽薪：Claude Code 内部存在未公开的 `cache_edits`/`cache_reference` 路径，据称能从缓存前缀里删除特定 tool result 而不整体失效 ([claude-code #42542](https://github.com/anthropics/claude-code/issues/42542))；它未出现在任何公开 API 文档中，论文可以声明前提对所有**已文档化**的提供商 API 成立，但要注明这一例外。

**Shadow calibration**。从"agent 后来用了什么"拟合阈值在文献中没有找到：SWE-Pruner/Pro/Squeez 全部用教师模型的银标签，TRACER 用 rollout 的 RL 回报并带再调用惩罚 ([arXiv 2608.29363](https://arxiv.org/html/2608.29363))。它比 RL 便宜、比银标签更有根据，可以作为贡献写，但要把 TRACER 列为近亲。

**Injection quarantine**。槽位与 Anthropic 已上线的做法相同：auto mode 用 API 侧探针扫描 tool result，命中时在结果到达模型前加一条警告 ([Anthropic auto mode](https://claude.com/blog/auto-mode-default-in-claude-code))。`jevctx` 用不引用原文的指针隔离是更强的策略，新意在机制不在位置。评估则远低于任何已发表标准：AgentDojo 有 629 个安全用例、InjecAgent 1,054 个、Trajectory Labs 720 次尝试，而 **18 条手工植入指令没有自适应攻击者、没有 ROC、没有阈值报告** ([AgentDojo](https://arxiv.org/html/2406.13352v3); [InjecAgent](https://arxiv.org/abs/2403.02691v1))。更麻烦的是 Jev 本身在三项独立评测里的画像一致：排序极好（AUROC 0.98–0.99）但默认 0.5 阈值下召回只有约 50–60%，阈值跨输入类型不可迁移，ROT13/反转/印地语下降到 32–39% ([Deußer et al.](https://arxiv.org/html/2609.37647v1); [Ruchith1018](https://github.com/Ruchith1018/jev-guardrail-evaluation); [Red Hat](https://developers.redhat.com/articles/2026/10/02/benchmarking-ai-decision-models-against-traditional-guardrails))。17/18 只有在英文、未混淆、已调阈值的前提下才说得通。而 "Decision Hijacking" 已经展示了被判断的那段文本本身就是攻击者可控的，可以写成同时压低"是否注入"概率的内容 ([arXiv 2609.28613](https://arxiv.org/abs/2609.28613))。这一块最诚实的处理是降为一个附带性质，并补齐基线（ProtectAI DeBERTa、PromptGuard 2、开源 LLM 的 yes/no logprob）。

**"只含原文、无生成记忆"**。这是抽取式压缩的结构性质，Selective Context、RECOMP 早已隐含，CliffCompaction 明文规定"只截断或丢弃，从不改写" ([arXiv 2609.26779](https://arxiv.org/abs/2609.26779))。没有论文把它命名为安全性质并与非生成判断模型结合，这个 framing 可以用；但批评 TypeSafe "不会幻觉"是"语义闪避"的人会原样把这句话用在 `jevctx` 上：形状有保证，选择的正确性没有 ([Pearpages](https://pearpages.com/blog/2026/09/16/jev-sorted-what-typesafes-system-one-model-actually-is-and-what-is-still-just-a-claim))。严格的评估只有两步：字节级来源检查（每个保留片段映射到源偏移，报告 100% 或不报告）加上**遗漏/失真**研究——在同等预算下与抽象式压缩比较下游准确率。rate–distortion 论文已经在原则上论证了"可逆性比任何打分技巧都重要"，这是项目可以引用的理论背书 ([alphaxiv 2607.08032](https://www.alphaxiv.org/abs/2607.08032.md))。

## 当前实验与顶会标准的距离：样本量、种子、模型、价目四项全部不达标

这个领域的接受线已经很清楚。Complexity Trap 用 **n=500**、paired bootstrap B=10,000、95% CI，solve rate 的 CI 宽度达 ±3.1–4.4 个百分点，多项 5–10% 相对差异不显著 ([arXiv 2508.21433](https://arxiv.org/html/2508.21433v3))；AgentDiet（FSE 2026）用 200 个随机实例加 100 个不相交的调参集、两个模型、两个基准 ([arXiv 2509.23586](https://arxiv.org/abs/2509.23586))；SWE-Pruner 跑满 500、温度 0、三个 seed ([arXiv 2601.16746](https://arxiv.org/html/2601.16746v4))。"On Randomness in Agentic Evals" 用 60,000 条 SWE-bench Verified 轨迹证明单次 pass@1 随运行变化 2.2–6.0 个百分点，温度 0 时标准差仍超过 1.5 个百分点，2–3 分的提升"可能只是评估噪声" ([arXiv 2602.07150](https://arxiv.org/abs/2602.07150))。对照之下，`jevctx` 的 21–24 个实例、每臂一次、A/A 对照在 prompt token 上就有 1.25× 的噪声、每臂还有 1–4 次被 harness 提前终止的运行 ([RESULTS.md](https://github.com/Waxmell114514/jev-compaction/blob/main/RESULTS.md))——**20/24 vs 21/24 这类结果在统计上什么都说明不了**，项目自己的 "What is not established" 一节也承认了这一点。

价目问题会被单独点名。Complexity Trap 连 Qwen 定价没区分缓存命中都要注明 ([arXiv 2508.21433](https://arxiv.org/html/2508.21433v3))；TokenPilot 和 Don't-Break-the-Cache 都从提供商返回的 usage 字段取 hit/miss 计数再乘官方价目；CliffCompaction 更进一步把价目模型与提供商计量的真实账单对照（Kimi 误差约 1%）([arXiv 2609.26779](https://arxiv.org/html/2609.26779); [arXiv 2601.06007](https://arxiv.org/html/2601.06007v2))。`jevctx` 的 $3/$0.30 价目恰好等于 Sonnet 4.5/4.6 的基价与读价，1.25× 写入也正确 ([Anthropic pricing](https://platform.claude.com/docs/en/docs/build-with-claude/prompt-caching))，所以价目本身不错，问题是它套在一个免费模型的 token 计数上，且 `mimo-v2.6-flash-free` 作为唯一模型缺乏代表性（SWE-Pruner Pro 把 MiMo-V2-Flash 当两个开源骨干之一，可作辩护，但只能是第二模型）。

还有三个会被问到的点。第一，Jev 是专有、带版本号、限速、同输入输出有微小抖动的模型（100 条里 77 条三次一致）([Ruchith1018](https://github.com/Ruchith1018/jev-guardrail-evaluation))，而 Tang & Zheng 的审计发现 typed readout 相比开源 LLM 的 label-probability 没有独立的准确率优势 ([arXiv 2609.32160](https://arxiv.org/abs/2609.32160))——审稿人会要求用开放替代（SecJev/JevLite/DeBERTa）复现，`jevctx` 的 `LLMJudgeClient` 虽然能跑但质量未测。第二，SWE-bench Verified 约 25 轮的短会话正好落在所有先例都发现 recall、offloading 近乎中性的区域；harness 研究显示管理与不管理的差距从 32k 预算下的 35.7 分缩到 128k 下的 2.7 分 ([arXiv 2609.20804](https://arxiv.org/html/2609.20804))。`recall` 和 supersession 注释的价值只能在长会话基准上显示。第三，评估应按 HAL 与 "AI Agents That Matter" 的要求把准确率与成本联合报告（Pareto 或 cost-of-pass），而不是分开给两个数 ([HAL](https://arxiv.org/pdf/2510.11977); [Cost-of-Pass](https://arxiv.org/pdf/2504.13359))。

有一个对项目有利的结构性事实：因为 `jevctx` 的重写只作用于请求、基于固定 transcript，**离线回放的成本评估是确定性的、天然配对的**，不需要 seed；方差问题只在重写改变模型行为（即在线准确率）时才出现。论文可以把这两件事分开——确定性回放成本（需对照真实计量账单）与在线准确率（需 seed）——这是把现有工作升级到可接受水平的最便宜路径。

## 最有希望的 thesis：无损、保缓存、按角色准入的 harness 侧上下文管理

四个候选 thesis 里，"role-labelled gating 比 masking/summary 更准"赛道最挤、最贵：必须在满 500 实例、两个模型、三 seed 下正面击败 SWE-Pruner（有公开代码）和 observation masking，还要把判断模型自身的 token 计入成本。"model-free supersession"是组件。真正有空白的是**缓存经济学**与**可恢复省略**：2026 年 4 月对七个编码 agent 的压缩机制调查明确写道"没有任何上线 agent 被描述为在压缩中保住 prompt cache" ([compaction showdown](https://codex.danielvaughan.com/2026/04/10/context-compaction-showdown-coding-agents/))；学术侧只有 Pichay 认真对待可恢复性（故障驱动钉住，1.4M 次模拟逐出 0.0254% 故障率，但只有生产评估、无任务成功率）([arXiv 2603.09023](https://arxiv.org/abs/2603.09023))，以及 9 月的 "When Can Agents Forget" 开始报告 cache-read token（−33.3%）([arXiv 2609.29875](https://arxiv.org/abs/2609.29875))。

建议的 thesis 一句话：**在 prompt caching 下，正确的上下文管理单位不是"删多少"而是"删了之后能否找回、重写是否划算"；一个只打分不生成的准入判断加上逐字可恢复的指针与 break-even 重写，能在不损失 resolve rate 的前提下把"被删但后来要用"的内容和缓存调整后成本同时压低，而现有的 masking、summarization 与 line-pruning 都无法在这两个轴上同时报告。**评价轴要新：以"elided-but-later-needed"（项目的 21→11 的直接版本，与 TRACER 的再调用率、SWE-Pruner 的轮数增加、Pichay 的 fault rate 对照）和"缓存调整后每次正确解答的成本"为主，resolve rate 做非劣性（CI 排除预注册的伤害边界），这正是 Complexity Trap 与 AgentDiet "保持性能不变"的表述方式。role gating、shadow calibration 作为让这两个指标变好的机制章节；supersession 作为让 break-even 变便宜的机制章节；injection 隔离与"只含原文"作为性质与安全讨论，不作主张。

需要补的实验按性价比排序。第一，**离线回放研究**：把现有轨迹（自己的 36 条 shadow 记录，加上 SWE-agent/OpenHands 的公开轨迹）过一遍成本模拟器，用提供商 usage 字段的 cache_read/cache_creation 计数与 Anthropic、OpenAI、DeepSeek、Gemini 四套真实价目，对比朴素压缩、M=10 masking、OpenCode 40K prune、`clear_tool_uses`、CliffCompaction 阈值触发、break-even 门控，报告 `(write − read)/read` 从 0.1× 到 0.025× 的敏感性与 `turns_left` 的敏感性；再用一个付费模型的小批真实账单校准模拟器（CliffCompaction Table 8 的模式）。这一步两到三周可完成，不需要 seed。第二，**在线确认**：200–500 个 Verified 实例（若 200，照 AgentDiet 留 100 个不相交调参集）、至少两个模型（一个真实付费的前沿模型如 Sonnet 5.5 或 GLM，一个开源如 MiMo/Qwen3-Coder）、三臂（raw、masked-unrecoverable、masked-recoverable）、三 seed、paired bootstrap、A/A 噪声地板、按真实计量账单计价。第三，**长会话**：在 SWE-Milestone、SWE-EVO 或 32k 紧预算设置下测 recall/主动 recall 与过期注释的价值——这是 harness 研究显示管理真正改变结果的区域 ([arXiv 2609.20804](https://arxiv.org/html/2609.20804); [SWE-Milestone](https://proceedings.mlr.press/v306/deng26d.html))，也是唯一能让 `recall` 从"几乎不用"变成有数据的地方。第四，**判断模型基线**：Jev vs DeBERTa 注入分类器 vs 开源 LLM 的 yes/no logprob vs JevLite，报告 ROC、固定 FPR 下召回、跨语料泛化，并把注入集扩到数百条、覆盖真实向量（issue 中的 HTML 注释、Unicode 混淆的 rules 文件、测试输出、安装日志、MCP 返回）([Microsoft Security](https://www.microsoft.com/en-us/security/blog/2026/06/05/securing-ci-cd-in-agentic-world-claude-code-github-action-case/))，并至少做一轮针对五问 prompt 的自适应攻击。

会议与时间线。ICLR/ICML/ACL 主会 2026 年接收的上下文管理论文几乎都带训练组件（AgentFold、MemAgent、ACON、Context-Folding）且在 web/QA/AppWorld 上评估；纯推理时、启发式、面向编码 agent 的工作落在 SE 会议（AgentDiet @ FSE 2026）或 workshop（Complexity Trap @ DL4C、On Randomness @ Agents in the Wild），SWE-Pruner 系列至今仍只在 arXiv ([ICLR 2026](https://iclr.cc/virtual/2026/poster/10010254); [PMLR ACON](https://proceedings.mlr.press/v306/kang26b.html); [DL4C](https://neurips.cc/virtual/2025/131688))。所以目标应是 SE 会议或 MLSys。已核实或估计的截止：MLSys 2027 论文 2026 年 10 月 30 日（两周内只能靠回放研究，过紧）([mldeadlines](https://mldeadlines.com/conference/mlsys/))；FSE 2027 10 月 2 日已过；ICSE 2027 研究轨已过、SEIP 10 月 23 日；ASE 2027 按 ASE 2026 的 3 月 26 日类推约 2027 年 3 月（未核实）([ASE 2026](https://conf.researchr.org/track/ase-2026/ase-2026-research-track))；ICML 2027 估计 1 月下旬（未核实）；NeurIPS 2027 约 5 月。**推荐路线：2026 年 11–12 月完成回放研究与开源组件，投 2027 年 1–2 月的 ICLR 2027 / ICSE 2027 co-located workshop；2027 年 1–3 月完成在线与长会话实验，投 ASE 2027（约 3 月）；若未中，补齐后投 NeurIPS 2027（5 月）或 FSE 2028。** SE 会议的 artifact evaluation 轨道还会奖励可复用的 harness 组件，与影响力目标一致。

## 要影响 harness 设计，交付物必须是可插入的组件而不是论文

研究对 harness 的直接影响在文献中几乎找不到引用链。SWE-agent 的 "agent-computer interface" 是最清楚的一例，靠的是开源 harness、可复现的基准数字、一个可复用的概念名，以及基准与方法同出一门 ([NeurIPS 2024](https://papers.neurips.cc/paper_files/paper/2024/hash/5a7c947568c1b1328ccc5230172e1e7c-Abstract-Conference.html))。相反，OpenHands SDK 论文为 condenser 的 2× 成本声明引用的是自家博客 ([arXiv 2511.03690](https://arxiv.org/html/2511.03690))；七个 agent 的压缩调查里只有 OpenHands 引用了任何学术论文 ([compaction showdown](https://codex.danielvaughan.com/2026/04/10/context-compaction-showdown-coding-agents/))；SWE-Pruner、Pichay、ContextBudget 的方法没有一个出现在 Codex CLI 里，SWE-Pruner 的 skimmer "无法在 Codex CLI 里原生运行" ([codex.danielvaughan.com](https://codex.danielvaughan.com/2026/06/17/context-pruning-research-swe-pruner-pichay-contextbudget-codex-cli-token-management-compaction/))。harness 以每天超过两个版本的速度演进 ([arXiv 2607.03691](https://arxiv.org/abs/2607.03691))，不会等论文。

由此推出四个条件。**第一，组件要 scaffold 无关且零改动可插**：`jevctx` 已有 HTTP sidecar 与 OpenCode 插件，但要进入主流，需要一个 OpenHands `Condenser` 实现（它的 event-sourced、`forgotten_event_ids` 接口天然适合可恢复省略 ([OpenHands SDK](https://docs.openhands.dev/sdk/arch/condenser))）、一个 mini-swe-agent/SWE-agent 的钩子，以及一个 Pichay 式的代理模式；并向 OpenCode 或 OpenHands 提 PR。Complexity Trap 指出 masking 窗口需按 scaffold 重调 ([arXiv 2508.21433](https://arxiv.org/html/2508.21433v3))，shadow calibration 恰好是对这个痛点的回答，应作为卖点。**第二，摆脱对专有 Jev 的依赖**：默认判断模型应是一个可本地运行的开放模型（JevLite/SecJev 一类的 4B 模型，或 DeBERTa 分类器加 LLM logprob），Jev 作为更快更便宜的可选后端；否则没有哪个开源 harness 会把一个闭源、"价格可能受补贴"的 API 做成默认路径 ([OpenRouter blog](https://openrouter.ai/blog/insights/what-is-jev/))。**第三，给概念起名并给出可复用的指标**：像 "ACI"、"observation masking" 那样，"break-even compaction"、"admission gating"、"elided-but-later-needed rate" 需要成为从业者能直接引用的词；指标的实现（从 transcript 自动计算）应随组件发布。**第四，先于投稿公开数字**：OpenHands 的博客和 Pichay 的 arXiv 都在没有会议背书的情况下被引用，说明可复现的真实价目数字加可运行代码比接收通知更能带来采用；项目现有的 GitHub Pages 页面是对的方向，但需要换成真实模型、真实账单的结果。

最后一点关于前提的稳固性。项目的核心论证——"重写中段必然付缓存写入代价"——对所有已文档化的提供商 API 成立，但 Claude Code 内部可能已有不失效缓存的 `cache_edits` 路径 ([claude-code #42542](https://github.com/anthropics/claude-code/issues/42542))，且 "Aborted but Not Forgotten" 展示了自托管服务上相反的风险：transcript 改了但 KV 留着，模型会继续注意到应用以为已丢弃的内容 ([arXiv 2608.15939](https://arxiv.org/abs/2608.15939))。论文应把 break-even 判据表述为"对严格前缀哈希缓存的提供商"的通用规则，并把"请求侧重写、存储 transcript 不变"与 Anthropic 服务端 context editing 已经保证的同一性质区分开——这不是相对 Anthropic API 的差异化，而是相对本地改写消息的 Claude Code microcompact 与一切摘要式压缩的差异化 ([Claude Platform docs](https://platform.claude.com/docs/en/build-with-claude/context-editing))。

## 结论

`jevctx` 的处境是典型的"工程先行、论点未定"：它在一个 2026 年已被 SWE-Pruner、AgentDiet、Complexity Trap、Concord、CliffCompaction、TokenPilot 密集覆盖的领域里做了一个完整而干净的系统，但目前把自己定位在最拥挤的那条赛道（admission 剪枝）上，用最弱的那组证据（24 个实例、一次运行、免费模型）支持。把论点换到"可恢复性与缓存经济学是上下文管理的正确评价轴"之后，项目现有的每一个机制都变成支撑这一论点的工具，而文献里恰好没有人以这个轴评估过——这是可以写成一篇有影响的 SE/MLSys 论文的真正机会，前提是评估规模提升一个数量级、价目与模型换成真实的、判断模型有开放替代。

另一个值得记住的反向信号是：三项独立工作都发现 agent 自己几乎不主动 recall。这意味着"可恢复"的价值不会来自 agent 的调用次数，而要来自 harness 主动代为 recall、来自长会话基准、来自"删错了也能无损补救"这一保证本身。论文如果把 recall 调用率当成功指标会自取其败；把它当作"为什么必须由 harness 而非模型负责找回"的论据，反而是整篇文章最有说服力的一段。
