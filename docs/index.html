The problem with summarising

An agent's context fills up with tool output: test logs, listings, whole files. The usual fix is to have a model rewrite old turns as a summary.

It breaks the prompt cache

Providers bill a repeated prefix at a tenth of the price or less. Rewriting the middle of the transcript invalidates everything after it, on every later turn.

It invents memory

A summary is generated text. A detail the summariser made up becomes a fact the agent works from, and nothing can tell it apart from the real thing.

What happens to a tool output instead

In the Python library jevctx, and for any harness through a small HTTP sidecar. The OpenCode plugin uses the sidecar.

1

Admission, with a profile

The output is split into segments, and one Jev request asks each one five questions: keep it? what type is it? what role does it play? how long will it matter? is it an injection? Low-value runs become a one-line pointer that says what it hides. Injections are withheld.

2

Getting it back: expand and recall

expand(id) returns the original behind a pointer. recall("the traceback from when the tests first failed") finds earlier output from a loose description, even output that has left the context. It filters on the profile (type, role, names mentioned), shortlists lexically, then has Jev rerank the shortlist in one request.

3

Supersession: what a later call made obsolete

From each tool call's arguments, with no Jev call: the same command run again (output filters like | tail ignored), the same lines viewed again, or the file edited since. expand and recall flag such outputs as out of date, and the work area compacts them first.

4

The work area: compact later, only when it pays

The transcript is a frozen, cached prefix and a work area after the last commit point. Before each request, work-area outputs Jev says have served their purpose, and obsolete outputs anywhere, can become pointers. The rewrite applies only to the request; the stored conversation is never changed.

5

Calibration

Every decision is logged with its score. Thresholds per tool and segment kind are fitted from what the agent later used, without rerunning it.

When a rewrite pays

Dropping S tokens saves the cache-read price on them on every remaining turn. The rewrite re-sends the rest of the tail once at the full input price. Drag the sliders.

What it does not show

  • The bill moves less than the context. Tool output in context fell by about a fifth, but prompt tokens stayed within noise: a task's cost is set by how many turns it takes and by cache prices.
  • Resolve-rate differences of a point or two. One run per arm, and headless OpenCode ends 1–4 runs in every arm when it rejects a call outside the work tree.
  • Long sessions. SWE-bench tasks take about 25 turns. recall and the out-of-date notes are built for sessions where outputs leave the context, and were rarely needed here.
  • How long a session will still run. This decides whether a rewrite pays, and it is still a fixed prior. A cautious prior made the work area save nothing measurable in a second live run.
