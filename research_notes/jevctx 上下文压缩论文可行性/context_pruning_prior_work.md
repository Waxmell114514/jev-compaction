# Prior work on context compaction / pruning of tool output for LLM coding agents (2024 – Oct 2026)

Scope: closest academic and industrial prior art to jev-compaction (`jevctx` + OpenCode plugin): a small decision-only model scoring each tool-output segment at admission (keep / type / role / lifetime / injection), one-line pointer elision with `expand` and `recall`, model-free supersession, cache-aware "work area" tail compaction, and thresholds calibrated from shadow logs of later use. Research conducted 2026-10-14. Everything below was verified against the primary arXiv page / vendor page unless flagged "(secondary)".

Citation index (exact titles, authors, IDs) is collected at the end of each section's findings; all URLs inline.

## Key Question 1: SWE-Pruner (and its successors): venue, method, numbers, goal definition, turns/cost

### Takeaway
SWE-Pruner (SJTU, arXiv Jan 2026, preprint, no venue found) is the closest academic analogue: a separate 0.6B line-level pruner conditioned on an agent-written natural-language "goal hint", applied at tool-output admission; it reports 23–38% token and 27–36% cost reduction on SWE-Bench Verified with ~flat resolve rate and *fewer* rounds. Its July 2026 successor SWE-Pruner Pro drops both the separate model and the goal hint, reading the agent's own hidden states — an independent finding that goal conditioning is not necessary, matching the project's offline result. Neither offers recovery of pruned bytes, role labels, cache-aware scheduling, or usage-derived labels.

### Cited Findings
- **SWE-Pruner: Self-Adaptive Context Pruning for Coding Agents**, Yuhang Wang, Yuling Shi, Mo Yang, Rongrui Zhang, Shilin He, Heng Lian, Yuting Chen, Siyu Ye, Kai Cai, Xiaodong Gu (corresponding author at sjtu.edu.cn). arXiv:2601.16746, v1 23 Jan 2026, v4 7 May 2026; cs.SE; arXiv preprint, no conference venue listed; code on GitHub. — [arXiv abs](https://arxiv.org/abs/2601.16746v2)
- Goal definition: the agent writes a "goal hint", a self-contained question (e.g. "How is authentication handled?") passed via an optional `context_focus_question` parameter added to file tools such as `cat`/`grep`; if omitted the skimmer is bypassed and full output is returned. In multi-turn tasks the agent generates a hint each round; in single-turn tasks the task description is the hint. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- Skimmer: Qwen3-Reranker-0.6B backbone, fusion of hidden states from layers 7/14/28, CRF head over retain/prune, line kept if score > 0.5; only last two layers + fusion + CRF trained. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- Training labels: ~200k snippets from GitHub Code 2025 (195,370 files, 5,945 repos); teacher Qwen3-Coder-30B-A3B-Instruct generates task queries and binary line masks across nine task types; LLM judge (Qwen3-Next-80B-A3B-Thinking) filters to 61,184 samples. Labels are teacher-generated "silver" labels, **not** derived from downstream agent use. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- SWE-Bench Verified (Mini-SWE-Agent, 500 instances): Claude Sonnet 4.5 base 51.0 rounds, 353/500 (70.6%), 0.911M tokens, $0.504; +SWE-Pruner 41.7 rounds, 351/500 (70.2%), 0.701M (-23.1%), $0.369 (-26.8%). GLM 4.6 base 49.3 rounds, 277/500 (55.4%), 0.791M, $0.055; +SWE-Pruner 36.6 rounds, 274/500 (54.8%), 0.488M (-38.3%), $0.035 (-36.4%). — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- Turns: rounds decrease on SWE-Bench (18% Claude, 26% GLM) but **increase** for GLM on SWE-QA (Streamlink 18.2→25.0, Reflex 26.1→36.7, Conan 21.4→27.7), attributed to more file exploration after pruning; Figure 7 caption reports different round reductions (34.6% GLM / 18.3% Claude) than Table 1 — internal inconsistency. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- 50-instance comparison: SWE-Pruner 64% success / 41.1 rounds / 0.670M tokens vs vanilla 62% / 52.3 rounds / 0.972M; baselines LLMLingua2, RAG, LLM Summarize, LongCodeZip. Observation masking and history compressors (ACON, AgentFold) are explicitly *not* compared ("different problem": trajectory compression vs observation compression). — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- Skimmer latency: TTFT ~45 ms at 64 tokens, ~102 ms at 8,192 tokens; no end-to-end wall-clock. No recovery mechanism for pruned lines, no prompt-cache discussion, no analysis of needed-but-pruned content (Appendix H only checks AST validity). — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- Abstract-level claims: 23–54% token reduction on SWE-Bench Verified, up to 14.84x compression on LongCodeQA. — [arXiv abs](https://arxiv.org/abs/2601.16746v2)
- **SWE-Pruner Pro: The Coder LLM Already Knows What to Prune**, arXiv:2607.18213, submitted 20 Jul 2026, cs.CL, same corresponding author (xiaodong.gu@sjtu.edu.cn). Attaches a small head to the frozen agent backbone's last-layer hidden states (from the prefill it already does) to label each line keep/prune; length-aware embedding keyed to line count; balanced focal loss; per-line majority vote over token sigmoids at 0.5; pruned lines removed before entering history. — [arXiv HTML](https://arxiv.org/html/2607.18213)
- Pro training labels: ~22.6k samples from 6,252 trajectories across five public HF datasets, per-line keep labels produced by Claude Sonnet 4.6 (some outputs labelled "skeleton" = all kept). Counterfactual/usage labels not used. Linear probe on frozen hidden states: AUC 0.83, F1 0.63 (majority-class bound 0.46). — [arXiv HTML](https://arxiv.org/html/2607.18213)
- Pro results: SWE-Bench Verified MiMo-V2-Flash resolves 326→345 (+3.8%) but input tokens +7.4% and API calls 94.8→111.8; Qwen3-Coder-Next resolves 341→335 (-1.2%), input tokens -13.5%, API calls 131.9→139.8. Read-only benchmarks (SWE-QA, SWE-QA-Pro, Oolong): up to 39.4% token reduction. In-engine head adds ~15% wall time (p50 14.7%, p95 34.8%). Baselines: LLMLingua2, Selective Context, RAG, Self-Prune, LongCodeZip, SWE-Pruner; observation masking not compared. — [arXiv HTML](https://arxiv.org/html/2607.18213)
- Pro's thesis: the explicit per-turn goal-hint query of SWE-Pruner is unnecessary because the signal is already in the backbone; no dedicated ablation of goal-conditioning value was visible. — [arXiv HTML](https://arxiv.org/html/2607.18213)
- **Squeez: Task-Conditioned Tool-Output Pruning for Coding Agents**, Ádám Kovács (single author), arXiv:2604.04979, 4 Apr 2026, cs.SE, 7 pages. Task: given a query and one tool output, return "the smallest verbatim evidence block"; 11,477 examples (618 manually curated test); LoRA Qwen 3.5 2B; recall 0.86, F1 0.80, 92% of input tokens removed; beats zero-shot Qwen 3.5 35B A3B by 11 recall points. **No end-to-end agent evaluation**, no recovery mechanism. — [arXiv abs](https://arxiv.org/abs/2604.04979)

### Inferences
- The project's admission-time, separate-small-model design is structurally the same as SWE-Pruner; the differences are (a) segment-level yes/no + typed roles rather than line-level masks, (b) reversible pointer elision, (c) labels/thresholds from later use, (d) cache-aware scheduling. On raw removal fraction the project (~26%) is in SWE-Pruner's range (23–38%).
- SWE-Pruner Pro and the project's own offline AUC result converge on "goal conditioning adds little"; this is now a replicated finding, not a novelty for either side.
- SWE-Pruner Pro's mixed SWE-Bench result (more API calls, sometimes more tokens) and SWE-Pruner's SWE-QA round increase show that "pruned content later needed → re-fetch" is a real cost nobody in this line measures directly.

### Gaps
- SWE-Pruner affiliations and any peer-review venue: not stated on arXiv; unverified.
- SWE-Pruner v3/v4 changes (Apr–May 2026) not examined; numbers above are from v1 HTML.
- Squeez label-construction method (whether derived from what the agent later used) could not be verified from the abstract.

## Key Question 2: Observation masking / AgentDiet / observation pruning / OpenHands condensers — simplest baseline and how well it does

### Takeaway
The simplest baseline — replace observations older than M turns with a placeholder, no model call — halves SWE-agent cost on SWE-bench Verified with no significant solve-rate loss for most models (JetBrains/TUM "Complexity Trap", DL4C@NeurIPS 2025), and is matched by OpenCode's built-in token-budget prune. AgentDiet (PKU/ByteDance, FSE 2026) is the strongest published "rewrite observations with a small model" result (input tokens -40–60%, cost -21–36%, pass rate flat, with explicit "expired" category and KV-cache-aware edit placement). OpenHands' default condenser is LLM summarization (resolve 54% vs 53%, per-turn cost < half).

### Cited Findings
- **The Complexity Trap: Simple Observation Masking Is as Efficient as LLM Summarization for Agent Context Management**, Tobias Lindenbauer (JetBrains Research & TUM), Igor Slinko, Ludwig Felder (TUM), Egor Bogomolov, Yaroslav Zharov (JetBrains Research). arXiv:2508.21433, v1 29 Aug 2025, v3 27 Oct 2025 = camera-ready for the 4th DL4C workshop co-located with NeurIPS 2025. — [arXiv abs](https://arxiv.org/abs/2508.21433v3)
- Mechanism: observations older than M recent turns replaced with a placeholder (e.g. "Previous 8 lines omitted for brevity"); reasoning and actions kept. M=10 for SWE-agent; OpenHands needed M=58 (reusing 10 degraded performance). LLM-Summary: summarize N=21 turns, keep M=10, trigger at 31 turns, OpenHands-style prompt, T=0. — [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)
- Results (SWE-agent, SWE-bench Verified; solve / $ per instance): Qwen3-Coder-480B raw 53.4% / $1.29, masking 54.8% / $0.61 (-52.7%), summary 53.8% / $0.64; Gemini 2.5 Flash raw 32.8% / $0.41, masking 35.6% / $0.18 (-56.1%), summary 36.0% / $0.24; Gemini 2.5 Flash (thinking) raw 40.4%, masking 36.4%, summary 31.4% (both drops statistically significant); Qwen3-32B raw 17.0% / $1.12, masking 15.0% / $0.55. — [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)
- Why: observation tokens ≈ 84% of an average SWE-agent turn; masking needs no extra calls and takes effect after ~10 turns vs 31. LLM-Summary elongates trajectories (Gemini Flash 52 turns vs 44 masking vs 50 raw; Qwen-Coder ~15% longer than raw) — summaries act as a "reinforcing signal" that hides failure. Hybrid (mask early, summarize late with N=43) is 7% cheaper than masking, 11% than summary; naive N=21 hybrid was worse due to "compounding KV cache inefficiencies". Stated limitation: both triggers are fixed and non-adaptive; masking ignores whether observations are stale. — [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)
- The paper title "Does Thinking Longer Help? Observation masking in SWE-agent" given in the brief **could not be found**; the JetBrains observation-masking paper is the Complexity Trap above. — [WebSearch, no hit](https://arxiv.org/abs/2508.21433)
- **Masking Stale Observations Helps Search Agents -- Until It Doesn't: A Regime Map and Its Mechanism**, Haoxiang Zhang, Qixin Xu, Zhuofeng Li, Lei Zhang, Pengcheng Jiang, Yu Zhang, Julian McAuley; arXiv:2606.00408, 29 May 2026, cs.CL, 47 pp; code github.com/i-DeepSearch/observation-masking. Finding: masking gain vs. unmanaged accuracy follows an asymmetric inverted-U (plateau for weak retrievers, peak for strong retriever + mid-capacity model, "sharp collapse when the model is saturated"); mechanism is a token-for-turn trade: masking removes observations the model has mostly stopped attending to and rarely re-opens, extra turns help until masking removes evidence the model would have used. Backbones 4B–284B, three retrievers, offline + live-web search benchmarks. — [arXiv abs](https://arxiv.org/abs/2606.00408)
- **Reducing Cost of LLM Agents with Trajectory Reduction** (v1 title: "Improving the Efficiency of LLM Agent Systems through Trajectory Reduction"; system name AgentDiet), Yuan-An Xiao, Yingfei Xiong (Peking University), Pengfei Gao, Chao Peng (ByteDance). arXiv:2509.23586, v1 Sep 2025, v2 Mar 2026; DOI 10.1145/3797084, PACMSE vol. 3 (FSE issue), i.e. FSE 2026. — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2)
- AgentDiet waste taxonomy: *useless* (e.g. `__pycache__` in listings, verbose build/test output), *redundant* (str_replace_editor echoing old/new strings already in context), *expired* ("may no longer be necessary after the step is completed", e.g. grep hits discarded once the faulty file is found). A reflection module (GPT-5 mini, chosen over Haiku 3.5/Gemini 2.5 Flash/DeepSeek v3/Qwen 3) rewrites step s−a (a=2) only when it exceeds θ=500 tokens, replacing waste with a short takeaway (e.g. "individual test lines omitted; mostly PASSED"); replacement applied only if savings > θ. Hyperparameters hill-climbed on 100 held-out SWE-bench Verified instances. — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2)
- AgentDiet results (Trae Agent): SWE-bench Verified Claude 4 Sonnet input tokens 0.601×, cost 0.714×, pass 64.5→66.5%, steps 39.62→39.95; Gemini 2.5 Pro 0.591×, 0.623×, pass 50.5→52.0%; Multi-SWE-bench Flash Claude 0.596×/0.676×, pass 40.0→39.0%; Gemini 0.403×/0.559×, pass 21.7→22.7%, steps 57.2→43.9. Overall cost incl. reflection -21.1% to -35.9%; input tokens -39.9% to -59.7%. Aggressive baselines (Delete, Random) raise steps and cut pass to 58%. — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2)
- AgentDiet and KV cache: the reflection module cannot share the agent's KV cache (different system prompt/tools); editing step s−a invalidates cache for all later steps, so only the single step s−a is edited to bound invalidation; cost accounting uses cached-input prices. No recovery mechanism ("agent can recover via additional tool calls"); no systematic analysis of wrongly removed content. — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2)
- **OpenHands Context Condensation** blog, Calvin Smith, 9 Apr 2025: LLM summary of older turns once context passes a threshold, keeping recent exchanges; SWE-bench Verified subset: resolve 54% (condensation) vs 53% (baseline), per-turn cost "less than half", "up to 2x" cost reduction, but more turns because condensing consumes turns. No observation masking / tool-output truncation discussed; no recall metrics. — [openhands.dev blog](https://openhands.dev/blog/openhands-context-condensensation-for-more-efficient-ai-agents)
- OpenHands SDK: default `LLMSummarizingCondenser` truncates history beyond `max_size` (default 120) and replaces dropped events with an LLM summary; `keep_first` default 4. — [OpenHands SDK condenser docs](https://docs.openhands.dev/sdk/arch/condenser); an `llm_attention_condenser` variant also exists in older docs — [all-hands docs](https://docs.all-hands.dev/modules/python/openhands/memory/condenser/impl/llm_attention_condenser)
- **FocusAgent** (web agents, not coding): lightweight LLM extracts relevant lines from accessibility-tree observations, >50% observation reduction on WorkArena/WebArena. arXiv:2510.03204. — [arXiv abs](https://arxiv.org/abs/2510.03204)
- Production-scale evidence of the problem: GitHub Copilot traces (first week June 2026): function-call (tool result) messages = 28% of prompt tokens; compaction affects 7.8% of sessions / 22.6% of >100K sessions, median event drops 72.8% of prompt tokens, first call after compaction loses median 66.1% cache-hit rate, 34.3% of events erase ≥90% of cache hits; compaction takes median 22% of turn time. **Agentic Coding in the Wild: Characterizing GitHub Copilot at Production Scale**, Banruo Liu, Haoran Qiu, Íñigo Goiri, Rodrigo Fonseca, Ricardo Bianchini, Esha Choukse (Microsoft Azure Research / UIUC), arXiv:2608.00101, 30 Jul 2026. — [arXiv HTML](https://arxiv.org/html/2608.00101v1)

### Inferences
- The strong, cheap baseline the project must beat is windowed observation masking (M≈10) / OpenCode's 40K-token prune, both model-free. The project's distinctive claim therefore cannot be "removes tokens" but must be "removes the *right* tokens (role-aware) and keeps them recoverable with cache preserved".
- AgentDiet's "expired" category and its step-s−a placement to bound cache invalidation are the closest prior art to the project's supersession and work-area ideas, but AgentDiet uses a *generative* rewrite by an LLM (GPT-5 mini) — it is exactly the "model writes text" design the project avoids.
- "Masking Stale Observations" (2026) gives a theoretical reason why a usage-calibrated, recoverable scheme should dominate fixed masking: masking fails exactly when it removes evidence the model would later use.

### Gaps
- Complexity Trap's placeholder string and its OpenHands numeric results beyond "matched LLM-Summary" were not extracted in full (HTML truncated at 100k chars).
- "Masking Stale Observations" benchmark names and accuracy numbers not extracted (PDF unparseable; abstract gives none).

## Key Question 3: Context folding / AgentFold / ACON / Hermes / "context engineering" 2025–26 — judge-only models? "no hallucinated memory" claims?

### Takeaway
The dominant 2025–26 academic line (ACON, AgentFold, OpenHands/Hermes/Codex/Claude Code summarizers) uses a *generative* compressor that writes summaries; the only non-generative designs found are SWE-Pruner/SWE-Pruner Pro/Squeez (line classifiers), TRACER (retention-ratio policy), the rate–distortion paper's "reversibility beats scoring" argument, and CliffCompaction's "truncate/drop, never rephrase" rule. No paper was found that states "no hallucinated memory" as a named property of a decision-only judge, though CliffCompaction's faithfulness principle and the Amp/OpenAI "recursive summaries distort reasoning" observations motivate it.

### Cited Findings
- **ACON: Optimizing Context Compression for Long-horizon LLM Agents** (Microsoft / KAIST), arXiv:2510.00615, Oct 2025; listed at ICLR 2026 and ICML 2026 virtual sites. Refines natural-language compression guidelines by analysing cases where full context succeeds but compressed fails, then distils the compressor into a smaller model; AppWorld/OfficeBench/Multi-objective QA peak tokens -26–54%, >95% accuracy retained when distilled. Generative compressor. — [arXiv abs](https://arxiv.org/abs/2510.00615v2); [ICLR 2026 listing](https://iclr.cc/virtual/2026/10012467); [ICML 2026 listing](https://icml.cc/virtual/2026/poster/66270)
- **AgentFold: Long-Horizon Web Agents with Proactive Context Management**, Rui Ye et al. (15 authors incl. Pengjun Xie, Fei Huang, Jingren Zhou, Yong Jiang), arXiv:2510.24699, 28 Oct 2025. Agent itself learns a per-step "folding" op (granular condensation vs deep consolidation of whole sub-tasks); AgentFold-30B-A3B, SFT only; BrowseComp 36.2%, BrowseComp-ZH 47.3%. Generative, in-policy. — [arXiv abs](https://arxiv.org/abs/2510.24699)
- **What to Keep, What to Forget: A Rate–Distortion View of Memory Compaction in LLMs and Agents**, Ashwin Gerard Colaco, Nada Lahjouji (UC Irvine), arXiv:2607.08032, 9 Jul 2026. Frames KV eviction, prompt compression, summarization as one budget problem (max I(Z;Y|Q) s.t. I(Z;H) ≤ B); proposes COMPACT-Bench; central claim: "reversibility usually matters more than any scoring trick" — at equal budget a method that can recover discarded content beats one that cannot, especially on queries depending on the discarded material; eviction and summarization are irreversible, retrieval-backed/archival schemes are not. — [alphaxiv mirror](https://www.alphaxiv.org/abs/2607.08032.md)
- **CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents**, Trang Nguyen, Eulrang Cho, Bingqing Chen (CMU / Bosch Center for AI), Tim Dettmers (CMU), arXiv:2609.26779, 22 Sep 2026. Principle: compacted content stays faithful because it is only truncated or dropped, "never rephrasing or rewriting it"; never compacts a compaction (prior compacted block discarded). — [arXiv abs](https://arxiv.org/abs/2609.26779)
- **Memory Control Signals Emerge Before Action in Long Horizon Agents**, Mingxuan Wang et al., arXiv:2609.27286, 23 Sep 2026: the need for compression/recall is already encoded in the hidden state before each action; PaMER/PaMER+ combine state-guided compression with step-level restoration of only the history the current step needs (WorkBuddyBench; no numbers in abstract). — [arXiv abs](https://arxiv.org/abs/2609.27286)
- **TokenPilot: Cache-Efficient Context Management for LLM Agents**, Buqiang Xu … Ningyu Zhang (15 authors; code in zjunlp/LightMem2), arXiv:2606.17016, 15 Jun 2026. Motivation: pruning and memory eviction change layouts → prefix mismatch → cache invalidation. "Ingestion-Aware Compaction" stabilises prompt prefixes and removes environmental noise at the ingestion gate; "Lifecycle-Aware Eviction" tracks residual utility and offloads segments on a conservative batch-turn schedule when task relevance expires. PinchBench/Claw-Eval cost -61%/-56% (isolated), -61%/-87% (continuous); accuracy "competitive"; scoring model and recoverability unspecified in abstract. — [papers.cool listing](https://papers.cool/arxiv/2606.17016)
- Hermes Agent (Nous Research): compression is a separate LLM summarizer call, default trigger 50%, gateway safety net 85% (secondary, mem0 blog) — [mem0 blog](https://mem0.ai/blog/how-hermes-and-claude-handle-context-compression-in-real-production-agents-(and-what-you-should-extract)); a deep-dive says summaries are treated as reference material, not instructions (secondary) — [akjamie deep dive](https://akjamie.github.io/post/2026-05-24-context-compressor-deep-dive/); community `hermes-lcm` keeps raw messages in SQLite so details are recoverable after compaction (secondary) — [hermesatlas](https://hermesatlas.com/projects/stephenschoettler/hermes-lcm). No "no hallucinated memory" metric found.
- Amp (Sourcegraph) replaced automatic compaction with Handoff (a separate model drafts the starting message of a new thread), plus user-driven edit/restore and a `read_thread` tool that uses a second model to extract relevant parts of another thread; @-mentioned files truncated to 500 lines / 2 KB per line; the guide is now archived. — [ampcode.com guide](https://ampcode.com/guides/context-management); a HackerNoon piece (secondary) attributes the shift to an OpenAI internal report that accuracy fell as "compacts" accumulated and recursive summaries distorted earlier reasoning — [HackerNoon](https://hackernoon.com/sourcegraphs-amp-tries-a-new-fix-for-the-long-conversation-problem)
- Anthropic, "Effective context engineering for AI agents", 29 Sep 2025 (Rajasekaran, Dixon, Ryan, Hadfield et al.): "One of the safest lightest touch forms of compaction is tool result clearing"; warns "overly aggressive compaction can result in the loss of subtle but critical context"; recommends maximise recall first then precision; Claude Code compaction keeps the five most recently accessed files. — [anthropic.com](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### Inferences
- The project's "judge never generates text" design has no direct named precedent in the papers found; the closest kin are classifier-style pruners (SWE-Pruner line CRF, Squeez) and CliffCompaction's non-rewriting rule. The combination "classifier + pointer + verbatim restore" is what the rate–distortion paper argues for in principle but does not implement for coding agents.
- The Hermes/Codex/OpenHands/Claude Code mainstream is generative summarization; its known failure modes (trajectory elongation, recursive-summary drift, cache loss) are the project's selling points, and can be cited as motivation rather than claimed as discoveries.

### Gaps
- No source found that uses the phrase "no hallucinated memory" or reports a hallucination-in-summary metric for agent compaction; treat as unclaimed in the literature (not verified absent).
- TokenPilot full text (whether its utility tracker is a model or rules) not read.
- "When History Is Multimodal: Rethinking Context Management for Long-Horizon Agents" (arXiv:2608.29897) surfaced in search but was not read.

## Key Question 4: Production harness practice (Claude Code, Codex CLI, Cursor, OpenHands, OpenCode, Gemini CLI, Amp, Pi) and "elide + reference" pointers

### Takeaway
Every major harness now has a model-free tool-result pruning layer plus LLM summarization: Claude Code "microcompact" and the Anthropic API `clear_tool_uses_20250919` (placeholder replaces old tool_result, no inference cost, invalidates cache); OpenCode's `compaction.ts` prune (keep newest 40K tokens of tool output, placeholder keeps tool name + args so the model can re-read; stored session untouched, no model call), ported to Pi as `pi-context-pruning`; Codex CLI `tool_output_token_limit` cap + summary (remote encrypted blob for OpenAI models); Gemini CLI compresses at 70% and can summarize shell output; OpenHands LLM condenser; Amp manual handoff. "Elide to a one-line placeholder that still names the tool and args" is standard; what is not standard is a learned per-segment decision, typed roles, a `recall` search over elided bytes, or a cache-price-driven trigger.

### Cited Findings
- Anthropic API context editing, `clear_tool_uses_20250919` (beta header `context-management-2025-06-27`): once context exceeds a threshold the API clears the oldest tool results in chronological order, replacing them with placeholder text; `clear_tool_inputs` optionally clears the call parameters; `exclude_tools` protects named tools; "clearing content modifies the prompt structure, breaking the match requirement for cache hits". — [platform.claude.com context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)
- Anthropic cookbook "Context engineering: memory, compaction, and tool clearing" (Isabella He, 20 Mar 2026): clearing is a sub-transcript operation with no inference cost; defaults trigger 100K, keep 3 tool uses, `clear_at_least` exists "so each firing frees enough tokens to justify that cache invalidation"; compaction `compact_20260112` default trigger 150K (min 50K), summarizer call costs an extra inference; demo: clearing 128,740→43,060 tokens (-67%), compaction probe preserved 3/3 high-level facts but 0/3 obscure appendix values; cookbook placeholder "[cleared to save context]" with `tool_use` block retained. — [Claude cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- Claude Code micro-compact (third-party ClaudeLog, unverified against Anthropic sources): introduced in Claude Code v1.0.68; removes old tool calls/results while keeping recent context; distinct from auto-compact (full summarization) and `/compact` (user-directed). — [ClaudeLog](https://claudelog.com/faqs/what-is-micro-compact/) (secondary). Third-party source-code readings claim count-based and time-based (cache-TTL) triggers and "cache-aware editing" via API cache edits, with compactable tools = file reads, shell, grep, glob, web fetch, edits — [Medium, pbellapu09](https://medium.com/@pbellapu09/how-claude-code-manages-infinite-sessions-without-blowing-the-context-window-8bccb35387fe) (secondary, could not be fetched: 403); CSDN analysis frames microcompact as a no-LLM layer run before each request ahead of autocompact/fullcompact — [CSDN](https://deepseek.csdn.net/6a3fb6ce662f9a54cb850ea2.html) (secondary).

## Key Question 5: Prior use of segment "role" (change-site / evidence / navigation) as gating signal, or thresholds calibrated from what the agent later used (counterfactual usage labels)?

### Takeaway
No prior work was found that labels tool-output segments by *role in the edit workflow* (code to be changed vs evidence vs navigation vs noise) and gates elision on it. The nearest ideas are AgentDiet's useless/redundant/expired taxonomy (per waste type, not per role), SWE-Pruner Pro's "skeleton" label, TRACER's per-*tool* retention ratios learned from consequence-attributed RL with a re-invocation penalty, and Decision-Aware Memory Cards' "would including this change the next action" utility (LLM-judged, retrieval setting). Training/threshold calibration from observed later use is partially present only in TRACER (outcome model from rollouts); no one reports it as shadow-log calibration of admission thresholds.

### Cited Findings
- **TRACER: Per-Tool Context Retention for LLM Agents via Consequence-Attributed Reinforcement Learning**, Ziqi Lin, Ye Wu, Mengying Yang, Xu Liu, Yizhou Liu, Qiang Ke, Qin Guo, arXiv:2608.29363, 29 Aug 2026. REINFORCE policy assigns a query-conditioned retention ratio per tool output (Beta-parameterised) using only information available at compression time; reward = task success + token use + event-local recall penalty for post-compression tool re-invocations; a learned outcome model compares the chosen ratio vs full retention per tool (interventional validation Spearman ρ=0.66, 82% top-3 overlap, 84% sign agreement). Tokens -29–46% vs keep-all across truncation/summarization/Self-Info compressors, +15–18% beyond a tool-type-conditional static policy; LOCA-bench -18–25% tokens; cross-backbone transfer 18–40%. Baselines: keep-all, uniform-0.5, recency, token-proportional, tool-type-conditional. No restore mechanism: "the agent re-invokes the tool to recover it". Setting: production e-commerce data-analysis agent (120 queries), not coding. — [arXiv HTML](https://arxiv.org/html/2608.29363)
- **Decision-Aware Memory Cards: Counterfactual-Inspired Context Selection and Compression for Tool-Using LLM Agents**, Xinyu Guan, Qianyang Zhao, Yuming Deng, arXiv:2606.08151, v1 6 Jun 2026, v4 21 Sep 2026, accepted ICONIP 2026 (Springer CCIS). CICL ranks retrieved files/tests/traces/rules/memories by expected effect on the agent's next action (not similarity), builds an instance context graph, compresses selected evidence into typed memory cards; works with hosted LLM judges, local surrogates or lightweight rankers. 50 SWE-bench Verified file-retrieval instances: Qwen3.6-Plus reranking BM25 top-50 raised hit@1 0.58→0.78, MRR@10 0.634→0.790; cards saved 44.93 tokens/query. "Causal" here means counterfactual-inspired utility, not formal identification. — [arXiv abs](https://arxiv.org/abs/2606.08151)
- SWE-Pruner Pro labels include a "skeleton" category (whole output kept) alongside per-line keep; labels are Claude-Sonnet-4.6-generated, not usage-derived. — [arXiv HTML](https://arxiv.org/html/2607.18213)
- AgentDiet classifies waste as useless / redundant / expired and tunes θ, a, b on 100 held-out instances by hill-climbing on cost/pass; it does not label *roles* of kept content. — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2)
- The Complexity Trap explicitly lists as a limitation that masking "ignores whether observations are stale" and that triggers are non-adaptive — i.e. role/staleness-aware gating is identified as open. — [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)
- OpenCode DCP implements model-free supersession-like dedup (same tool + same args → keep newest output only). — [GitHub Opencode-DCP](https://github.com/Opencode-DCP/opencode-dynamic-context-pruning)

### Inferences
- Role labels (change_site/evidence/navigation/noise) gating elision, and the reported effect "role gating halved elision of code later edited (21→11)", appear to be novel as a mechanism and as a measured outcome; the closest precedent (TRACER) conditions on *tool type*, which the project's own baseline already subsumes.
- Calibrating thresholds from shadow logs of actual later use is distinct from (a) teacher-LLM silver labels (SWE-Pruner, Pro, Squeez) and (b) RL reward from rollouts (TRACER); it is cheaper than (b) and more grounded than (a). I found no paper describing it; it should be presented as a contribution but with the caveat that TRACER's re-invocation penalty is a cousin.
- Model-free supersession ("same command rerun / same lines re-read / file edited since") exists piecemeal in DCP dedup and AgentDiet's "expired" and "redundant" categories (the latter LLM-judged); a rules-only, model-free formulation across all three cases does not appear to be published, but it is a modest engineering contribution rather than a research novelty.

### Gaps
- Could not confirm whether any 2026 paper uses the exact "change-site" / "evidence" vocabulary; searches on counterfactual usage labels and role gating returned only the works above.
- Decision-Aware Memory Cards full text not read (PDF unparseable); implementation of the counterfactual judge is only abstract-level.

## Key Question 6: Any prior work reporting "elided output that the agent later needed" as a metric?

### Takeaway
No paper reports a direct "elided-but-later-needed" count as a headline metric. The closest proxies are TRACER's post-compression tool re-invocation rate (p_recall, used as a penalty), SWE-Pruner / SWE-Pruner Pro round/API-call increases (interpreted as re-exploration), AgentDiet's step-count comparison for aggressive baselines, the Masking-Stale-Observations mechanism analysis ("removes evidence the model would otherwise have used"), and Anthropic's cookbook probe (compaction preserved 0/3 obscure facts).

### Cited Findings
- TRACER records "tool re-invocations after compression (the recall rate, p_recall)" and penalises it in the reward; it warns that "aggressive compression may trigger costly tool re-invocations that offset the initial savings". — [arXiv HTML](https://arxiv.org/html/2608.29363)
- SWE-Pruner: GLM rounds rise on SWE-QA after pruning (e.g. Reflex 26.1→36.7) "attributed to more file exploration after pruning"; no analysis of needed-content removal. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- SWE-Pruner Pro: API calls per SWE-Bench run rise 94.8→111.8 (MiMo) and 131.9→139.8 (Qwen3-Coder-Next) with pruning; pruned lines not recoverable. — [arXiv HTML](https://arxiv.org/html/2607.18213)
- AgentDiet: Delete/Random baselines "increase steps and lower Pass% (Delete drops to 58%)", used as indirect evidence of over-removal; no systematic wrong-removal analysis. — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2)
- Masking Stale Observations: masking hurts "when masking removes evidence the model would otherwise have used"; observations removed are those "the agent rarely re-opens". — [arXiv abs](https://arxiv.org/abs/2606.00408)
- Anthropic cookbook compaction probe: high-level facts 3/3 preserved, obscure appendix values 0/3 preserved. — [Claude cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- Rate–distortion paper: argues the right evaluation axis is recoverability of discarded content under a shared budget (COMPACT-Bench). — [alphaxiv](https://www.alphaxiv.org/abs/2607.08032.md)
- Complexity Trap reports trajectory length per strategy (Gemini Flash: 52 / 44 / 50 turns for summary / masking / raw) as a side effect metric. — [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)

### Inferences
- "Elided output later edited/used" (the project's 21→11 metric) is a sharper, directly attributable version of what TRACER measures via re-invocations; it is defensible as a new evaluation metric for the coding-agent setting, and the project should contrast it explicitly with re-invocation counts and round deltas.

### Gaps
- No source found that counts `expand`/re-read of previously elided segments in a coding agent; absence is based on this search pass only.

## Key Question 7 (synthesis): Which parts of jev-compaction are already done elsewhere, and which are not?

### Takeaway
Token-level pruning of tool output at admission with a small separate model (SWE-Pruner), model-free placeholder elision with re-read affordance (OpenCode/Pi/Anthropic API), goal-conditioning being unnecessary (SWE-Pruner Pro), cache-aware placement of edits (AgentDiet, CliffCompaction, TokenPilot) and "truncate, never rewrite" faithfulness (CliffCompaction) are all published. Not found anywhere: typed *role* gating, `recall` by loose description over elided bytes with a decision-model rerank, a closed-form cache-price trigger (`dropped × turns_left × read_price > tail × (write − read)`), threshold calibration from shadow logs of later use, and "elided-but-later-edited" as a metric. The project's evaluation (21–24 instances, one run per arm) is far below the field's bar (500 instances, multiple models) and its headline removal (~26%) is at the low end of SWE-Pruner (23–38%) and well under AgentDiet (40–60% input tokens) and masking (~50% cost).

### Cited Findings
- Already done — admission-time separate small pruner on coding-agent tool output: SWE-Pruner 0.6B, 23–38% tokens, cost -27–36%, 500 SWE-Bench Verified instances, two models. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1)
- Already done — goal conditioning unnecessary: SWE-Pruner Pro removes the goal query and separate model. — [arXiv HTML](https://arxiv.org/html/2607.18213)
- Already done — pointer placeholders naming tool+args with stored transcript untouched and no model call: OpenCode prune / pi-context-pruning; Anthropic `clear_tool_uses`. — [pi-context-pruning README](https://cdn.jsdelivr.net/npm/pi-context-pruning@1.1.0/README.md); [platform.claude.com](https://platform.claude.com/docs/en/build-with-claude/context-editing)
- Already done — model-free windowed masking as strong baseline: ~50% cost, flat solve rate. — [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)
- Already done — cache-invalidation-aware edit placement: AgentDiet edits only step s−a; CliffCompaction perfect-caching cost model (shrink = full invalidation, cache read ≈ 1/5–1/6 of uncached), cache-read cost -80%, 8K budget costlier than 16K due to re-prefill; TokenPilot ingestion-gate prefix stabilisation; Anthropic `clear_at_least` "to justify that cache invalidation". — [arXiv HTML v2](https://arxiv.org/html/2509.23586v2); [arXiv HTML](https://arxiv.org/html/2609.26779); [papers.cool](https://papers.cool/arxiv/2606.17016); [Claude cookbook](https://platform.claude.com/cookbook/tool-use-context-engineering-context-engineering-tools)
- Already done — "truncate/drop, never rephrase" and "never compact a compaction": CliffCompaction (Terminal-Bench 59.16→61.42%, cost -25–65%). — [arXiv abs](https://arxiv.org/abs/2609.26779)
- Already done — supersession/dedup of identical tool calls (model-free): OpenCode DCP. — [GitHub Opencode-DCP](https://github.com/Opencode-DCP/opencode-dynamic-context-pruning)
- Already done — per-tool retention learned from consequences incl. re-invocation penalty: TRACER (non-coding). — [arXiv HTML](https://arxiv.org/html/2608.29363)
- Already argued in principle — reversibility beats scoring: rate–distortion paper. — [alphaxiv](https://www.alphaxiv.org/abs/2607.08032.md)
- Evaluation bar in the field: SWE-Pruner 500 instances × 2 models; AgentDiet 2 benchmarks × 2 models with 100-instance held-out tuning; Complexity Trap 5 model configs with significance tests. — [arXiv HTML v1](https://arxiv.org/html/2601.16746v1); [arXiv HTML v2](https://arxiv.org/html/2509.23586v2); [arXiv HTML v3](https://arxiv.org/html/2508.21433v3)

### Inferences
- Not found elsewhere (candidate contributions): (1) role-typed gating (change_site/evidence/navigation/noise) and its measured effect on later-edited code; (2) `recall` = profile filter → BM25 → decision-model rerank over elided segments, a retrieval-backed reversibility mechanism inside a coding harness; (3) an explicit closed-form expected-cost trigger for compacting only the uncached tail; (4) shadow-log calibration of admission thresholds from what the agent later used; (5) a decision-only (never generative) judge also screening for prompt injection at admission; (6) "elided-but-later-needed" as a first-class metric.
- Weak or non-novel claims to avoid: "~26% removed with resolve rate unchanged" (SWE-Pruner, AgentDiet, masking all report larger savings at scale); "goal conditioning doesn't help" (already in SWE-Pruner Pro); "stored transcript never rewritten" (OpenCode/DCP/Pi already do this); "no model call for supersession" (DCP dedup).
- The strongest framing for a paper is: a *reversible, cache-preserving, role-aware* admission policy, evaluated on recoverability (elided-then-needed, expand/recall hit rate) and cache-adjusted cost against windowed masking, OpenCode prune, SWE-Pruner and CliffCompaction as baselines — none of which currently report recoverability.

- Prompt-injection screening of tool output as part of a pruning judge: not searched in this pass (out of the brief's core scope); no claim made either way.
