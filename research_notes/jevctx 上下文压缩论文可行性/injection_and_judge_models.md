# Prompt-injection quarantine at tool-output ingress, and score-only "decision/judge" models (Jev) — survey as of 2026-10-14

Scope note: this covers (1) injection defenses for tool-using / coding agents and their benchmarks, and (2) TypeSafe's Jev and the "score-but-never-generate" model class, plus (3) whether "context contains only original bytes" is claimed elsewhere and how to evaluate "no invented memory". All Jev facts are from vendor docs, OpenRouter docs, or third-party/arXiv evaluations posted 2026-09-16 to 2026-10-05; TypeSafe has published no paper, weights, or architecture, so everything about Jev's internals is unverifiable.

---

## KQ1. Injection defenses for tool-using agents: landscape, benchmarks, detector TPR/FPR, and whether "18 planted instructions / 0 FP on 2,499 segments" is an acceptable eval

### Takeaway
The field has converged on (a) architectural/capability defenses (CaMeL, Rule of Two, sandboxing) that are provably or structurally robust, and (b) detectors/classifiers (PromptGuard 2, ProtectAI DeBERTa, Lakera, Jev-as-guardrail) that look good on static benchmarks but are broken by adaptive attacks (>90% ASR against 12 defenses in Nasr et al. 2025) and inflate 8+ AUC points under distribution shift. The standard agent benchmark is AgentDojo (97 tasks, 629 security cases, 27 injection tasks); "18 planted instructions" is one-to-two orders of magnitude smaller than any published eval and has no adaptive-attacker component, so a reviewer will treat 17/18 as a smoke test, not evidence.

### Cited Findings

**Benchmarks**
- AgentDojo (Debenedetti, Zhang, Balunović, Beurer-Kellner, Fischer, Tramèr; arXiv 2406.13352, v3 24 Nov 2024; NeurIPS 2024 D&B): 97 realistic tasks, 629 security test cases; four suites with 6/5/7/9 = 27 injection tasks (Workspace/Slack/Travel/Banking). Code: https://github.com/ethz-spylab/agentdojo — [AgentDojo abs](https://arxiv.org/abs/2406.13352); [AgentDojo HTML v3](https://arxiv.org/html/2406.13352v3)
- AgentDojo Table 5 (GPT-4o): no defense — benign utility 69.0%, utility under attack 50.0%, targeted ASR 57.69%; **PI detector (ProtectAI DeBERTa-v3-base-prompt-injection-v2): benign utility 41.49%, utility under attack 21.14%, targeted ASR 7.95%**; repeat-user-prompt 85.53% / 67.25% / 27.82%; tool filter 73.13% / 56.28% / 6.84%; data delimiting (spotlighting) 72.66% / 55.64% / 41.65%. I.e. the off-the-shelf detector cut ASR ~7x but destroyed ~40% of benign utility via false positives on tool outputs — [AgentDojo HTML v3](https://arxiv.org/html/2406.13352v3)
- AgentDojo "important message" attack reaches 57.7% targeted ASR on GPT-4o; undefended ASR across models ranges 0.95% (Command-R+) to ~57.7% (GPT-4o) — [AgentDojo HTML v3](https://arxiv.org/html/2406.13352v3)
- InjecAgent (UIUC, ACL Findings 2024, arXiv 2403.02691): 1,054 test cases, 17 user tools, 62 attacker tools; ReAct-prompted GPT-4 compromised ~24% (base), ~47% with "enhanced" hacking prompt — [InjecAgent](https://arxiv.org/abs/2403.02691v1)
- RedCode (NeurIPS 2024; Guo, Li, Song et al.): RedCode-Exec >4,000 instances across 25 vulnerability types in a Docker sandbox; RedCode-Gen 160 prompts; agents refuse unsafe operations less when described in natural language than as code — [RedCode (Microsoft Research page)](https://www.microsoft.com/en-us/research/publication/redcode-multi-dimensional-safety-benchmark-for-code-agents/); [NeurIPS poster](https://neurips.cc/virtual/2024/poster/97521)
- AutoDojo (arXiv 2606.15057, 2026): generative benchmark; defenses strong on static AgentDojo attacks still fail — on GPT-4o-mini it lifts PIGuard's ASR from 0.0% to 28.0% — [AutoDojo](https://arxiv.org/html/2606.15057v3)
- PI-Hunter (arXiv 2606.12737, 2026): automated red-teaming for exposing and localizing prompt injections — [PI-Hunter](https://arxiv.org/pdf/2606.12737)
- OWASP Top 10 for Agentic Applications 2026 (published 2025-12-09): ASI01 "Agent Goal Hijack" is #1; OWASP LLM Top 10 2026 keeps Prompt Injection #1; posture is architectural ("assume the instruction boundary can be bypassed; restrict actions and destinations") — [Cycode summary](https://cycode.com/blog/owasp-top-10-agentic-applications/); [letsdatascience](https://letsdatascience.com/news/owasp-keeps-prompt-injection-atop-2026-llm-risks-02083f8b)

**Architectural / system-level defenses**
- CaMeL (Google DeepMind et al., "Defeating Prompt Injections by Design", arXiv 2503.18813, v2 24 Jun 2025): capability-based data-flow layer around the LLM; solves 77% of AgentDojo tasks with provable security vs 84% undefended; with Claude 3.5 Sonnet, 0 successful attacks over 949 vs 8 for next-best (Tool Filter) — [CaMeL](https://arxiv.org/pdf/2503.18813)
- MELON (ICML 2025, arXiv 2502.05174): re-runs the agent with the user prompt masked and compares tool calls; claims best attack-prevention/utility trade-off on AgentDojo; an independent adaptive red-team still found residual ASR — [MELON](https://arxiv.org/pdf/2502.05174); [ICML poster](https://icml.cc/virtual/2025/poster/44447)
- Task Shield (Jia, Wu, Qin, Squicciarini; ACL 2025 Long, arXiv 2412.16682): test-time task-alignment check per instruction/tool call; AgentDojo GPT-4o: 2.07% ASR, 69.79% utility; baselines were data delimiting, PI detector, prompt sandwiching, tool filtering — [Task Shield](https://arxiv.org/abs/2412.16682); [ACL](https://aclanthology.org/2025.acl-long.1435)
- IPIGuard (tool-dependency-graph defense) and AttriGuard (causal attribution of tool invocations, arXiv 2603.10749, 2026): AttriGuard's table shows IPIGuard with highest utility among system-level defenses on Gemini-2.5 (BU 73.91% vs 57.61% no-defense) with low-but-nonzero ASR (~2%) — [AttriGuard](https://arxiv.org/html/2603.10749v2)
- Meta "Agents Rule of Two" (2025-10-31): an agent session should hold at most two of {process untrustworthy input, access sensitive data, change state / communicate externally} "until prompt injection can be reliably detected" — [Simon Willison summary](https://simonw.substack.com/p/new-prompt-injection-papers-agents); [critique](https://kenhuangus.substack.com/p/the-rule-of-two-vs-reality-why-metas)
- Spotlighting/datamarking (Microsoft, arXiv 2403.14720): on GPT-3.5-Turbo ASR ~50% → <3%; authors note datamarking "may be ineffective" for code inputs — [Spotlighting](https://arxiv.org/pdf/2403.14720)
- StruQ (SFT) and SecAlign (DPO): originally reported GCG ASR 0.04 and 0; "A Critical Evaluation of Defenses against Prompt Injection Attacks" (Jia, Shao, Liu, Jia, Song, Gong; arXiv 2505.18333, 23 May 2025) re-evaluates: under adaptive GCG, StruQ ASV 1.00/1.00 (OpenPromptInjection/MMLU-PI), SecAlign 0.46/0.88; utility drops (Llama-3-8B 0.65/0.45 → StruQ 0.54/0.35, SecAlign 0.48/0.34); Instruction Hierarchy (GPT-4o-mini) keeps utility but Combined-Attack ASV 0.68/0.75 — [Critical Evaluation](https://arxiv.org/html/2505.18333)
- Same paper's detector numbers: **PromptGuard (v1) FPR 0.89 / FNR 0.00 / AUC 0.92 on OpenPromptInjection; FPR 0.84 / AUC 0.75 on MMLU-PI** — i.e. high AUC coexisting with ~85–89% FPR; Attention Tracker FPR 0.00 but adaptive FNR 0.96–1.00. Conclusion: "AUC alone is insufficient" — [Critical Evaluation](https://arxiv.org/html/2505.18333)
- "The Attacker Moves Second" (Nasr, Carlini, Sitawarin, Schulhoff, Hayes, …, Tramèr; arXiv 2510.09023, 10 Oct 2025): adaptive attacks (gradient descent, RL, random search, human red-teaming) bypass 12 recent defenses with >90% ASR for most, where most had reported near-zero — [Attacker Moves Second](https://arxiv.org/abs/2510.09023)
- SoK "Prompt Injection Attacks on Agentic Coding Assistants" (Maloyan, Namiot; arXiv 2601.17548, 24 Jan 2026): 78 studies, 42 attack techniques, 18 defenses; ASR >85% against SOTA defenses with adaptive attacks; most defenses <50% mitigation; argues for architectural mitigations over ad-hoc filtering — [SoK](https://arxiv.org/abs/2601.17548)

**Classifier / guard models**
- Meta PromptGuard 2 (LlamaFirewall paper, arXiv 2505.03574): recall at 1% FPR — 86M: 97.5%, 22M: 88.7%; PromptGuard 1: 21.2%; 86M English AUC 0.98, multilingual 0.995; AgentDojo evaluation assumes a 3% utility cost from FPs — [LlamaFirewall](https://arxiv.org/pdf/2505.03574); [Groq model page](https://console.groq.com/docs/model/llama-prompt-guard-2-86m)
- "When Benchmarks Lie" (Fomin; ICLR 2026 workshop "Agents in the Wild"): standard same-source splits inflate AUC by 8.4 points; LODO per-dataset gaps 1–25%; 28% of top SAE features are dataset shortcuts; **PromptGuard 2, LlamaGuard and LLM-as-judge detect only 7–37% of indirect attacks targeting agents; PG2/LlamaGuard "cannot evaluate agentic tool injection due to architectural limitations"** — [When Benchmarks Lie](https://www.iclr.cc/virtual/2026/10016274)
- "Defusing Explosive Prompts" (arXiv 2609.22510, 2026): zero-shot PromptGuard 2 AUC 0.9313 vs PIGuard 0.8533 but recall at default threshold 0.136 at FPR 0.0008; fine-tuning raised FPR on Wikipedia host corpus to 47% (host-domain shortcut) — [Defusing](https://arxiv.org/pdf/2609.22510)
- InjecGuard (arXiv 2410.22770): NotInject benchmark for over-defense (339 benign prompts with trigger words) — [InjecGuard](https://arxiv.org/pdf/2410.22770)
- Red Hat benchmark (Geada, Misiura, Cyril; 2026-10-02; NeMo-Guardrails prompt-injection set, class-balanced, English-only): deberta-v3-base-prompt-injection-v2 (200M) accuracy 89.01%, allowed-recall 0.9684 (derived FPR 3.16%), blocked-recall 0.8307, median latency 80 ms; Qwen3.6-35B 89.31%, FPR 4.04%; **Jev-1.13.0 86.35%, allowed-recall 0.9754 (derived FPR 2.46%), blocked-recall 0.7787, median latency 348 ms**; Laya 85.44%, FPR 22.32%. Conclusion: "pre-trained classifiers remain highly competitive"; decision models did not reliably beat classifiers or LLM-judges — [Red Hat](https://developers.redhat.com/articles/2026/10/02/benchmarking-ai-decision-models-against-traditional-guardrails)
- Lakera: vendor claims FPR 0.1–0.2% on internal benchmark; ~92.5% on its own PINT; competitor-cited FPR 12.4% (NotInject) / 17.4% (WildGuard-benign); no neutral head-to-head with ProtectAI found — [CourtGuard](https://arxiv.org/html/2510.19844v1); [Constellation (competitor)](https://constellationnetwork.io/blog/gate-ai-prompt-injection-benchmark/); [Lakera eval guide](https://docs.lakera.ai/docs/evaluation-overview)

**Vendor agent mitigations (ingress screening of tool results)**
- Anthropic, "auto mode default in Claude Code" (claude.com blog, 2026-08-07): "tool results are scanned by probes for potentially malicious instructions"; an API-side probe inspects external content (web pages, file contents, tool outputs) and, when flagged, **adds a warning to Claude's context before the result reaches the model** (i.e. tag-and-warn, not strip/quarantine); separate action classifier checks intent alignment. Evals: human study (1,053 testers) humans blocked 13.6% of dangerous commands vs auto mode 89%; Apollo Research red-team classifier miss rate 12% → 7% (synthetic); Trajectory Labs 72 held-out indirect-injection scenarios ×10 = 720 attempts: Claude Fable 5 / Opus 5 / Sonnet 5 in auto mode 0 successes; GPT-5.6 Sol Codex Auto-review 5.83%, Codex Full Access 19.03%; Claude bypassPermissions 0.09%; production May–June 2026: 6.3% of manually-approved sessions vs 2.4% auto-mode sessions contained an unrequested harmful action (severity ≥7). Caveat in post: classifiers "do not eliminate risk" — [Anthropic auto mode](https://claude.com/blog/auto-mode-default-in-claude-code)
- Secondary reporting: the action classifier (Sonnet 4.6) sees user messages and tool calls but not reasoning or tool results; auto mode default on Pro/Max/Team from 2026-08-14 — [implicator.ai](https://www.implicator.ai/anthropic-claude-code-auto-mode-default/); [Backslash critique: 17% miss rate on overeager actions; "probabilistic, not a security boundary"](https://www.backslash.security/blog/claude-code-auto-mode-can-one-model-guard-another)
- Claude in Chrome: 23.6% ASR without mitigations (123 cases, 29 scenarios); two classifiers (incoming content + per-action); support page claims <0.08% ASR in internal testing; GA post: 17.6% for Opus 4.5 before safeguards under a newer grader — [Claude for Chrome](https://www.anthropic.com/news/claude-for-chrome); [support](https://support.claude.com/en/articles/12902428); [GA post](https://claude.com/blog/claude-in-chrome-generally-available); [prompt-injection-defenses research page](https://www.anthropic.com/research/prompt-injection-defenses)
- OpenAI Codex: GPT-5-Codex system card — Instruction Hierarchy training + Codex-specific injection eval suite; GPT-5.2-Codex — default sandbox disables network, restricts edits to workspace; cloud Codex isolated container, network off by default — [GPT-5-Codex system card](https://cdn.openai.com/pdf/97cc5669-7a25-4e63-b15f-5fd5bdc4d149/gpt-5-codex-system-card.pdf); [Codex system card](https://cdn.openai.com/pdf/8df7697b-c1b2-4222-be00-1fd3298f351d/codex_system_card.pdf); [GPT-5.2-Codex](https://deploymentsafety.openai.com/gpt-5-2-codex)
- Third-party "IH-Benchmark" (2026-07-29) reports open-weight models obey ~4 in 10 tool-output injections and that coding contexts degrade instruction-hierarchy scores (unverified blog) — [IH-Benchmark](https://codex.danielvaughan.com/2026/07/29/ih-benchmark-instruction-hierarchy-robustness-coding-agents-codex-cli-tool-output-trust-defence/)

### Inferences
- Quarantining flagged tool-output segments behind a non-quoting pointer is a *stronger* ingress policy than Anthropic's documented "add a warning to context" probe, but it is the same architectural slot (API-side screening before the model reads the result). Novelty is in the mechanism, not the slot.
- The dominant failure mode for ingress detectors in published work is **false positives on benign tool output** (AgentDojo PI detector: −27.5 points benign utility; PromptGuard v1 FPR 0.84–0.89; Laya 22% FPR). jevctx's 0 FP on 2,499 real segments is therefore the more interesting half of its claim and the one a reviewer will want on more diverse corpora (test logs, install logs, non-English READMEs, obfuscated text).
- "17/18 caught" without an adaptive attacker, without reporting the threshold/ROC, without a held-out set, and with 18 hand-planted strings is below the bar set by every cited paper: AgentDojo has 629 cases, InjecAgent 1,054, Trajectory Labs 720 runs, the independent Jev guardrail study 6,991 calls. Reviewers (per Critical Evaluation, Attacker Moves Second, When Benchmarks Lie) will demand: FPR/TPR curves at fixed FPR, adaptive attacks tuned to the five-question prompt, cross-corpus (LODO-style) generalization, and obfuscation/multilingual cases.
- Jev-as-guardrail already has three independent datapoints to compare against: Red Hat (accuracy 86.35%, blocked-recall 0.78, FPR 2.46%), Ruchith1018 (deepset AUC 0.986 but recall 58.6% at 0.5 threshold; thresholds do not transfer across input types; ROT13 39%, reversed 32%, Hindi 33%), and Deußer et al. (116-example injection set: AUROC 0.982 but recall ≈50% at 0.5). A 17/18 result is consistent with these only if jevctx uses a lower threshold than 0.5, which would need to be stated.

### Gaps
- No AgentDojo "code" variant or SWE-bench injection benchmark found; the SoK (2601.17548) may list one in the body (only abstract read).
- BIPIA and WASP primary papers not fetched (BIPIA is used as a dataset in the Ruchith1018 study).
- Could not confirm the "11.2%" Claude-for-Chrome number; only 23.6%, 17.6% and <0.08% are documented.
- Anthropic has not published the probe's own TPR/FPR; only end-to-end ASR.
- The 12 defenses in "Attacker Moves Second" were not enumerated from the abstract page.

## KQ2. Injection vectors specific to coding agents (repo files, README, issues, test output, install logs, rules files, MCP)

### Takeaway
Every vector jevctx targets has a documented real-world exploit between March 2025 and June 2026: rules files (Pillar "Rules File Backdoor"), MCP/external content (Aim "CurXecute" CVE-2025-54135), GitHub issue/PR/HTML-comment text (Claude Code GitHub Action, fixed in 2.1.128 on 2026-05-05), and AGENTS.md. Vendors' responses were mostly sandboxing and least-privilege; none of the disclosed fixes was a content classifier.

### Cited Findings
- Pillar Security "Rules File Backdoor" (2025-03-18): hidden Unicode in `.cursorrules` / `.github/copilot-instructions.md` makes Copilot/Cursor emit malicious code that passes review; propagates through forks; Cursor said "not a vulnerability on their side", GitHub said users are responsible for reviewing suggestions — [GlobeNewswire release](https://www.globenewswire.com/de/news-release/2025/03/18/3044719/0/en/New-Vulnerability-in-GitHub-Copilot-and-Cursor-How-Hackers-Can-Weaponize-Code-Agents-Through-Compromised-Rule-Files.html); [Security Affairs](https://securityaffairs.com/?p=175593)
- Aim Labs "CurXecute" CVE-2025-54135 (CVSS 8.6, fixed Cursor 1.3 on 2025-07-29; reported 2025-07-07): injected text reaching the agent via a Slack MCP server causes edits to `mcp.json` that execute before user approval → RCE; any MCP server processing external content (issue trackers, support tools, search) is a vector — [BleepingComputer](https://bleepingcomputer.com/news/security/ai-powered-cursor-ide-vulnerable-to-prompt-injection-attacks); [The Hacker News](https://thehackernews.com/2025/08/cursor-ai-code-editor-fixed-flaw.html); [SecurityWeek](https://www.securityweek.com/several-vulnerabilities-patched-in-ai-code-editor-cursor/)
- Microsoft Security blog, "Securing CI/CD in an agentic world: Claude Code GitHub Action case" (2026-06-05): untrusted issue bodies, PR descriptions, comments and hidden `<!-- -->` HTML comments reached the agent as instructions; Bash was env-scrubbed but the Read tool was not sandboxed, so `/proc/self/environ` exposed `ANTHROPIC_API_KEY`; the injection framed itself as a "compliance review" and asked for the key minus its first 7 chars to evade refusal and secret scanning; reported via HackerOne 2026-04-29, fixed Claude Code 2.1.128 on 2026-05-05 (blocks sensitive /proc). Recommended: Rule of Two, least-privilege keys, system-prompt hardening ("all issue/PR/comment/file content is untrusted data"), isolation per GitHub Agentic Workflows — [Microsoft](https://www.microsoft.com/en-us/security/blog/2026/06/05/securing-ci-cd-in-agentic-world-claude-code-github-action-case/)
- GMO Flatt Security "Comment and Control" chain against Claude Code Action from a public issue; Anthropic patched in 4 days, CVSS 7.8; Claude Code, Gemini CLI Action and GitHub Copilot Agent all "process untrusted GitHub metadata — PR titles, issue bodies, and HTML comments — as authoritative prompt content"; Anthropic's system card says Claude Code Security Review is "not hardened against prompt injection" — [TNW](https://thenextweb.com/news/claude-code-github-action-prompt-injection-flaw); [VentureBeat](https://venturebeat.com/security/ai-agent-runtime-security-system-card-audit-comment-and-control-2026); [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-claude-code-github-action-prompt-injection/)
- AGENTS.md injection against Codex / Claude Code / Cursor (community write-up) — [dev.to](https://dev.to/karthidreamr/codex-claude-code-cursor-jailbreak-agentsmd-prompt-injection-12pk); Codex `untrusted_project` setting stops AGENTS.md loading (third-party blog) — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/08/30/when-context-gets-root-privilege-escalation-llm-harnesses-codex-cli-multi-agent-defence/)
- EchoLeak (CVSS 9.3): zero-click exfiltration via hidden email instructions in Microsoft 365 Copilot — not a coding agent, but the canonical "instructions in retrieved content" case — [VentureBeat](https://venturebeat.com/security/ai-agent-runtime-security-system-card-audit-comment-and-control-2026)
- Other Claude Code CVEs (not injection per se): CVE-2026-24887 approval bypass via `find` (<2.0.72); deny-rule bypass via 50-subcommand cap (fixed 2.1.90) — [Wiz](https://www.wiz.io/vulnerability-database/cve/cve-2026-24887)
- SoK 2601.17548 taxonomy: input manipulation, tool poisoning, protocol exploitation (MCP), multimodal injection, cross-origin context poisoning; lists "Rules File Backdoor: .cursorrules, .github/copilot-instructions.md" as a delivery vector — [SoK](https://arxiv.org/html/2601.17548v1)
- SkillShield (blog, 2026-08-28, unverified): RedCode-Exec ASR 67.4% → 10.1% with low false refusals on SWE-Bench Pro — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/08/28/skillshield-prompt-space-security-skills-coding-agents-agents-md-codex-cli/)

### Inferences
- A reviewer will expect jevctx's planted-instruction set to mirror these real vectors: hidden HTML comments in issues, Unicode-obfuscated rules files, "compliance-review" social framing, instructions inside test output and install logs, and MCP-returned content. The Microsoft case shows attackers specifically craft text to look benign to a refusal layer — a detector must be evaluated against such framing, not only against "ignore previous instructions" strings.
- Because vendors fixed these with sandboxing/least-privilege, a reviewer will ask what quarantine adds *on top of* Rule-of-Two-style capability limits, and whether a quarantined pointer can itself be a vector (e.g. the agent is tricked into dereferencing it).

### Gaps
- No academic paper found that benchmarks injections specifically in **test output or package-install logs**; the vectors are described in SoK and vendor posts but no dataset exists.
- Pillar's full technical report and Aim's original CurXecute post were not fetched (only press coverage).

## KQ3. What Jev / TypeSafe is; size, pricing, training, docs, calibration, users; novelty of "a model that only answers constrained questions"

### Takeaway
Jev (TypeSafe AI, founder Diogo Almeida, ex-OpenAI; ~$40M raised; launched 2026-09-15, public hosted API ~2026-09-21) is a proprietary, non-generative model with three typed primitives (Choice, Score, Noul=yes/no probability), $0.042/M input tokens, output free, 32k-token state, ~70–500 ms latency, trained with an undisclosed "RLCD" method; no paper, weights, parameter count or architecture are published. Independent work (Deußer et al. 2609.37647; Tang & Zheng 2609.32160; Red Hat) finds it well-calibrated in aggregate (pooled ECE 0.028 on choice) and cheap/fast, but with **no demonstrated accuracy advantage over label-probability readouts of open LLMs**, and the "score-only" idea is a direct descendant of classifier heads, reward models, cross-encoders/rerankers and constrained-decoding judges — so the novelty jevctx can claim is in the *use* (ingress quarantine + compaction), not in the judge class.

### Cited Findings

**Identity, access, pricing**
- OpenRouter community docs: Jev is "a structured decision model from TypeSafe", first of its System One models; "does not produce reasoning traces, explanations, or free-form text"; primitives Choice (option + per-option probability + confidence), Noul (probability of yes), Score (probability-weighted position on an ordered scale, per-level probabilities, confidence); model ID `typesafe/jev-1.13`, alias `~typesafe/jev-latest`; endpoints `POST https://openrouter.ai/api/alpha/decisions` and `POST https://openrouter.ai/api/v1/systemone`; context 32,000 tokens (state + questions); output tokens free; cookbooks include "gating agent tool calls" and "auto-approving coding agent permission prompts" — [OpenRouter Jev docs](https://openrouter.ai/docs/guides/community/jev)
- TypeSafe direct API: single route `POST https://api.typesafe.ai/v1/systemone`, model `jev-latest`; not OpenAI-compatible — [LiteLLM passthrough docs](https://docs.litellm.ai/docs/pass_through/typesafe); [OpenRouter model page](https://openrouter.ai/~typesafe/jev-latest)
- OpenRouter blog (2026-09-21, updated 09-24): early access from 2026-09-15; proprietary, no weights or paper; input $0.042/M as of 2026-09-21, output free; TypeSafe lists 64k per request (32k state + longest question); Score capped at 10 levels; calibration "holds in aggregate" per TypeSafe; probabilities vary slightly between identical calls (author observed Noul 0.52 vs 0.49 on same ambiguous input); confidence for Choice/Score measures distribution concentration, not correctness; not suited to arithmetic, date math, deterministic rules — [OpenRouter blog](https://openrouter.ai/blog/insights/what-is-jev/)
- Launch post "Introducing System One Models & Jev" (typesafe.ai; sources date it 2026-09-15, page metadata shows 2026-10-13 — discrepancy): founder Diogo Almeida; training method named "RLCD — Reinforcement Learning for Calibrated Decisions"; claims Jev "can't hallucinate" because "schema matching is guaranteed, thus we can confidently add 0% into the plots"; "calibrated: higher confidence means higher accuracy"; latency 70–500 ms, "40x–200x faster"; headline 193.6x faster / 444.6x cheaper from four code-defined workflows whose reference labels are the *average of GPT-6 Astra and Claude Fable 5.1 predictions*, not human labels (post admits bias); lists "guardrail, and detect jailbreaks of LLM prompts, reasoning traces, and/or outputs" as a use case; model size not stated; pricing "may be subsidized" — [TypeSafe launch post](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
- Pearpages teardown (2026-09-16): $40M raised, ~2 years in stealth (citing The Register); Choice max 255 options; workflow-eval table: Jev 67.8% agreement at $0.0004/case, 0.4 s; GPT-5.6 Terra 67.9%, $0.0304, 10.1 s; GPT Sol 74.1%; Claude Opus 5 73.1%; Haiku 4.5 53.6%; Jev worst on invoice processing (61.8%, 13–18 points behind others); no ECE/Brier/reliability diagram published by vendor; no single-token-logprob baseline; "decomposing judgments into small typed questions improved every LLM in the table, independent of Jev" — [Pearpages](https://pearpages.com/blog/2026/09/16/jev-sorted-what-typesafes-system-one-model-actually-is-and-what-is-still-just-a-claim)
- Documented rate limits per Deußer et al. citing TypeSafe docs: 1,200 req/min, 250,000 tokens/s — [2609.37647](https://arxiv.org/html/2609.37647v1)
- Secondary explainers (MarkTechPost 2026-09-19 — 403 on fetch; DataCamp; TrueFoundry; Requesty; sanity.io) exist but add no primary facts — [MarkTechPost](https://www.marktechpost.com/2026/09/19/typesafe-ai-releases-jev/); [DataCamp](https://www.datacamp.com/blog/system-one-models-jev); [TrueFoundry](https://www.truefoundry.com/blog/typesafe-ai-jev)

**Independent evaluations of Jev (accuracy, calibration, robustness, as-guardrail)**

### Inferences
- Jev is best described as a hosted, calibrated, zero-shot multi-task classifier/scorer with an API that enforces a typed schema. Prior art for "score but never generate": encoder classifier heads (DeBERTa-v3 injection detector, PromptGuard), reward models, Cohere Rerank / cross-encoders, NLI zero-shot classifiers (BART-MNLI), and LLM-as-judge with constrained decoding or next-token label probabilities — exactly the baselines Tang & Zheng and Deußer et al. use. The audit's finding that typed readout shows no independent accuracy advantage over label-probability readouts means a reviewer will insist jevctx compare Jev against (a) a DeBERTa injection classifier and (b) an open LLM's next-token yes/no logprob, not only against unmeasured `LLMJudgeClient`.
- The pricing claim ($0.042/M) is verified across OpenRouter, Deußer et al. and the launch post; "subsidized, expected to fall" is a vendor caveat worth repeating.
- Jev's injection-detection profile across three independent studies is consistent: excellent ranking (AUROC 0.98–0.99), conservative default threshold (recall ~50–60% at 0.5), near-zero FPR, thresholds non-transferable across input types, weak on obfuscation and non-English. jevctx's "17/18, 0 FP" is plausible for English, un-obfuscated plants at a tuned threshold — and a reviewer will ask for the threshold, the ROC, and obfuscated/non-English plants.
- JevOut/JevAdvBench show the judge itself is manipulable by benign-looking context; since the segment being judged *is* attacker-controlled, a reviewer will ask whether an injection can be written to also suppress the "is this an injection?" Noul (the Decision Hijacking paper's adaptive setting is the template).

### Gaps
- Model size, architecture, training data and RLCD details: not published by TypeSafe; unverifiable.
- Who uses Jev in production: no named customers found beyond OpenRouter integrations (Jev Router), WSO2 AI Gateway guardrail integration (benchmark repo) and LiteLLM passthrough.
- The 88.3% / 84.5% "modal agreement" subset figures come only from the Pearpages secondary summary.
- MarkTechPost article returned 403; its claims (waitlist status) not verified.
- TypeSafe `/decisions` naming: the project's reference to a `/decisions` endpoint matches OpenRouter's `/api/alpha/decisions`; TypeSafe's own documented route is `/v1/systemone`.

## KQ4. Is "context contains only original bytes, never generated text" claimed elsewhere? How to evaluate "no hallucinated memory" rigorously

### Takeaway
Extractive compression (Selective Context, LLMLinguа-family, RECOMP-extractive) implicitly has the property and RECOMP explicitly frames faithfulness and empty-summary abstention as goals, but none of the cited works claims it as a *safety* property or combines it with a non-generative judge; "no invented memory" is a structural guarantee of extractive selection, not an empirical result, and the empirical question is *omission* (what was dropped) rather than fabrication. HaluMem (Nov 2025) is the closest benchmark for memory hallucination, and no benchmark yet measures compaction faithfulness directly.

### Cited Findings
- Selective Context (Li et al., EMNLP 2023, 2023.emnlp-main.391; arXiv 2310.06201): prunes low-self-information tokens; 50% context cost cut with faithfulness drop of only 0.038 across four applications; 36% less inference memory, 32% less time; token deletion means no new text is produced but faithfulness is still a *measured drop*, not a guarantee — [arXiv](https://arxiv.org/abs/2310.06201v1); [ACL Anthology](https://preview.aclanthology.org/setup/2023.emnlp-main.391)
- RECOMP (ICLR 2024): extractive compressor "selects relevant sentences from retrieved document set"; states "a good summary should be faithful to the retrieved evidence documents"; can return an empty summary when retrieved documents are unhelpful (abstention) — [ICLR 2024 PDF](https://proceedings.iclr.cc/paper_files/paper/2024/file/bda88ed2892f5e61c9a9bf215c566913-Paper-Conference.pdf)
- LLMLingua (Microsoft): perplexity-based token dropping (secondary description only; primary faithfulness eval not fetched) — [systems-analysis.ru overview](https://systems-analysis.ru/eng/Prompt_compression)
- HaluMem (arXiv 2511.03506, Nov 2025): operation-level benchmark for hallucination in agent memory systems (extraction, updating, QA); memory systems produce "fabrication, errors, conflicts, and omissions"; argues end-to-end QA cannot localize where hallucination enters; errors form early and propagate — [HaluMem](https://arxiv.org/abs/2511.03506v2); [HF](https://huggingface.co/papers/2511.03506)
- "What to Keep, What to Forget: A Rate–Distortion View of Memory Compaction in LLMs and Agents" (arXiv 2607.08032, 2026): states no current benchmark measures compaction directly; proposes a COMPACT-Bench concept; reviews LongMemEval, SCBench, KVPress — [2607.08032](https://arxiv.org/pdf/2607.08032)
- Deußer et al. report Jev on LLM-AggreFact (fact-grounding) at 78.6% balanced accuracy and SummEval Spearman 0.554 — relevant if Jev is also used to judge faithfulness — [2609.37647](https://arxiv.org/html/2609.37647v1)
- Critics of TypeSafe's "can't hallucinate" framing: Goedecke calls it "a semantic dodge"; Maio: the model "constrains the shape of the output. It does not constrain the judgment." — [Pearpages](https://pearpages.com/blog/2026/09/16/jev-sorted-what-typesafes-system-one-model-actually-is-and-what-is-still-just-a-claim); [Maio](https://anthonymaio.substack.com/p/jev-the-language-model-that-wont)

### Inferences
- jevctx's "no invented memory" is true by construction *for the bytes that survive* (same argument as Selective Context / RECOMP-extractive), and a reviewer will accept it as a structural property only if the pipeline is shown to contain no generative step anywhere (including the pointer text, headers, or any `LLMJudgeClient` path). The same critics who called TypeSafe's "can't hallucinate" a semantic dodge will apply the identical objection: shape is guaranteed, selection correctness is not.
- Rigorous evaluation of "no hallucinated memory" therefore reduces to (1) a byte-provenance check — every retained span maps to an exact source offset (automatable, should be reported as 100% or not at all), and (2) an *omission/distortion* study: downstream task accuracy (e.g. SWE-bench-style resolution or needle-in-haystack recall over tool outputs) at matched token budgets vs abstractive compaction (Claude Code's own compaction, LLMLingua-2), plus HaluMem-style operation-level labeling of what was dropped, and a measurement of whether dropping segments *changes* agent actions (the MELON/Task Shield-style "does the trajectory diverge" metric). Quarantine adds a third axis: utility loss from false quarantines (the AgentDojo PI-detector utility collapse is the cautionary number).
- No one in the cited literature claims the combination "extractive compaction + non-generative injection judge → provenance-preserving, injection-quarantined context"; that framing is the defensible novelty, provided the eval is scaled.

### Gaps
- No paper found using "provenance-preserving context" or "original bytes only" as a stated safety property; this appears to be unclaimed in the literature surveyed (searched extractive compression, faithful summarization, memory hallucination).
- LLMLingua / LLMLingua-2 primary faithfulness numbers were not fetched.
- No benchmark exists for compaction faithfulness of *tool output* specifically (2607.08032 confirms the gap).

## What a reviewer would demand (synthesized checklist)

1. Scale and realism of the injection eval: hundreds of injection instances across the documented coding-agent vectors (issue/PR HTML comments, rules files with Unicode obfuscation, AGENTS.md, test output, install logs, MCP returns), not 18 hand-written strings — anchored to AgentDojo (629 cases), InjecAgent (1,054), Trajectory Labs (720 runs), Ruchith1018 (6,991 calls). Sources: [AgentDojo](https://arxiv.org/abs/2406.13352); [Microsoft Claude Code Action case](https://www.microsoft.com/en-us/security/blog/2026/06/05/securing-ci-cd-in-agentic-world-claude-code-github-action-case/)
2. Adaptive attacker: injections optimized against the five-question prompt and the Noul threshold (Decision Hijacking's score-feedback method; Nasr et al.'s >90% ASR finding). Sources: [2609.28613](https://arxiv.org/abs/2609.28613); [2510.09023](https://arxiv.org/abs/2510.09023)
3. Report ROC / recall at fixed FPR / the threshold used, and cross-corpus (LODO) generalization; AUC alone is explicitly rejected by Jia et al. and Fomin. Sources: [2505.18333](https://arxiv.org/html/2505.18333); [When Benchmarks Lie](https://www.iclr.cc/virtual/2026/10016274)
4. Baselines: ProtectAI DeBERTa-v3 injection classifier, PromptGuard 2 86M, an open LLM's next-token yes/no logprob, and the `LLMJudgeClient` path — because the audit finds no intrinsic advantage of typed readouts. Sources: [2609.32160](https://arxiv.org/abs/2609.32160); [Red Hat](https://developers.redhat.com/articles/2026/10/02/benchmarking-ai-decision-models-against-traditional-guardrails)
5. Utility cost of quarantine on benign tool output (false-quarantine rate on test logs, stack traces, non-English, encoded text), given the AgentDojo detector's −27.5 pt benign-utility hit and Jev's documented ROT13/reversed/Hindi weaknesses. Sources: [AgentDojo HTML](https://arxiv.org/html/2406.13352v3); [jev-guardrail-evaluation](https://github.com/Ruchith1018/jev-guardrail-evaluation)
6. Threat model clarity: what quarantine adds beyond Rule-of-Two / sandboxing, and whether the pointer can be dereferenced by a tricked agent. Sources: [Rule of Two](https://simonw.substack.com/p/new-prompt-injection-papers-agents); [CaMeL](https://arxiv.org/pdf/2503.18813)
7. "No invented memory": prove absence of any generative step (100% byte provenance), then measure omission/distortion vs abstractive compaction at matched budgets, HaluMem-style. Sources: [HaluMem](https://arxiv.org/abs/2511.03506v2); [2607.08032](https://arxiv.org/pdf/2607.08032)
8. Reproducibility caveat: Jev is proprietary, versioned (`jev-1.13-20260917`), rate-limited, and outputs vary slightly between identical calls (77/100 identical across runs); results must be pinned to a version/date and ideally replicated with an open stand-in (SecJev/JevLite or DeBERTa). Sources: [OpenRouter blog](https://openrouter.ai/blog/insights/what-is-jev/); [jev-guardrail-evaluation](https://github.com/Ruchith1018/jev-guardrail-evaluation)
